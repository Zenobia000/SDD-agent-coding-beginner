> 使用 Claude Code 的話，另外建一個 `CLAUDE.md`，內容只有一行 `@AGENTS.md`。
> `＜＞` 換成你的內容；用不到的條目整條刪掉，不要留著。

## 規格在哪

- 需求以 `1_requirements.md` 為準，架構以 `2_architecture.md` 為準。
- 兩份文件衝突時，**停下來問我**，不要自己選一個。
- 規格沒寫的行為，不要自己決定。列出來問我。

## 怎麼跑

```bash
＜安裝指令，例：pip install -e ".[dev]"＞
＜測試指令，例：pytest＞
＜啟動指令，例：uvicorn app.main:app --reload＞
```

說「完成」之前，必須跑過測試指令，並把結果貼出來。

## 範圍

- 一次只做一張票。發現需要改票以外的檔案，先問我。
- 不重構與這張票無關的程式碼。

## 套件

- **不准新增任何套件**，除非先說明理由並得到我同意。
- 允許的套件以 `＜pyproject.toml / package.json＞` 現有的為準。

## 秘密

- API key、密碼、token 一律從環境變數讀取，不准寫進任何檔案。
- 不准讀取或印出 `.env` 的內容。
- 範例設定檔用 `.env.example`，值一律填 `changeme`。

## 輸入與輸出

- 所有外部輸入（使用者輸入、API request、LLM 回傳）都要驗證格式，驗證失敗就拒絕，不要猜。
- 資料庫查詢一律用參數化，不准用字串拼接 SQL。
- 輸出到網頁的內容一律跳脫（escape），防 XSS。
- 錯誤訊息不准包含堆疊追蹤、資料庫內容或金鑰。

## AI 功能（系統本身有呼叫 LLM 時）

- LLM 的輸出必須通過 schema 驗證才能使用。
- ＜例：剩餘天數、金額、權限判斷＞ 一律由程式碼計算，不准採用 LLM 給的值。
- 使用者輸入的文字放進 prompt 時，要放在明確標記的區塊裡，並且當成資料，不是指令。

## 不准做的事

- 不准 `git push --force`、不准 `git add -A`、不准合併 PR。
- 不准刪除或修改測試來讓測試通過。
