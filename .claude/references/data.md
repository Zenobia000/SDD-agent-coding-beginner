# 資料層與管線

需要時查。可跑的實作在 [`../../labs/blocks/db/`](../../labs/blocks/db/) 與 [`../../labs/blocks/etl/`](../../labs/blocks/etl/)。

## 動手前三個問題

**誰是真相源？** 同一份資料兩個地方都能改，遲早不一致。

**可以重跑嗎？** 重跑會產生重複資料的管線，你不敢重跑，出事就沒救。

**壞掉會怎樣？** 下游有誰在讀？他們會發現嗎？

---

## Schema 的五個常見錯誤

**什麼都 nullable** → 之後每個查詢都要防空。不確定就先設 NOT NULL，放寬比收緊容易。

**沒有 `created_at`** → 出事時無法回溯。一律加，用 UTC。

**用浮點數存錢** → `0.1 + 0.2 != 0.3`。用整數存最小單位，或 `DECIMAL`。

**硬刪除** → 誤刪不可逆。重要資料用 `deleted_at`。

**沒有唯一約束** → 靠應用層防重複遲早會破。該唯一的在 DB 層加 `UNIQUE`。

外鍵刪除行為要明確選：CASCADE / RESTRICT / SET NULL。預設不代表你想要的那個。

索引要對應實際的查詢，不是「感覺會用到」。

## 管線四段

```
Extract → Transform → Validate → Load
```

**Extract**：單一來源失敗不該影響其他來源。重試要有上限，失敗要告警，不要靜默跳過。

**Transform**：轉不動的**單筆隔離**，不要整批失敗。上游一定會改格式，只是不會通知你——先正規化再解析。

**Validate**：最常被省略也最重要的一段。

**Load**：必須**冪等**。同一批跑兩次結果要一樣。

---

## Validate 的四類檢查

**筆數**：跟上批比變動超過門檻要人確認。

**非空**：關鍵欄位不可為空。

**型別與範圍**：日期在合理區間、金額不為負、列舉值在允許集合內。

**唯一性**：主鍵沒有重複。

每條都要能用程式跑並回傳 pass / fail。

**冷啟動是所有「跟上次比」邏輯的共同盲點**：前一批為空時，0 → N 的變動率是無限大。寫任何比對前先想「沒有上次的時候呢」。

## 那一行 if

```python
verdict = validate(rows, prev=db.latest())
if not verdict.ok:
    return Failed(verdict.reason)      # ← 不進 Load，保留上一版
db.upsert(rows)
```

**這一行就是「可信管線」和「自動產生髒資料機」的唯一差別。**

## 壞了怎麼發現

「有問題我會看 log」不會發生——沒有人會主動看 log。

驗證失敗時：不載入、保留上一版、寫一筆告警、下次成功時自動清掉。

## 選什麼存

單機、單使用者、十萬筆以下 → **SQLite**。這是預設。

需要多寫入者並行或交易一致性 → Postgres。

快取或 session → Redis。

檔案與圖片 → 物件儲存，DB 只存路徑。

純前端暫存 → localStorage。

換成別的通常是 ADR 等級的決定，值得寫下理由。

---

## Migration

加欄位可逆。**刪欄位、改型別不可逆**——分兩次部署（先停用、再刪），而且先備份。

不可逆的 migration 要寫進維運卡的「不可回滾操作」那一格。
