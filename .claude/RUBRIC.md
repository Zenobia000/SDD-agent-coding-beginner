# RUBRIC — 八站二元判準

> `/gate` 讀這份檔案。**判準是二元的：通過 / 未通過，不給分數。**
> 這份是判準的**單一真相源**。`curriculum/S*.md` 的「閘門」段與
> `curriculum/cards/gates.md` 必須與本檔一致，不一致以本檔為準。

---

## 怎麼用

```
① /gate 讀 .claude/.station 確定站別
② 從本檔找該站條目
③ 實際去看檔案 / 跑指令驗證（不可憑對話記憶）
④ 回報：通過 / 缺什麼 / 一個下一步
```

**沒辦法實際驗證的條目，標「未驗證」，不算通過。**

## S0 開機

| # | 判準 | 怎麼驗 |
|---|---|---|
| 1 | `claude` 可執行 | `claude --version` 有輸出 |
| 2 | 專案目錄存在且含 `.claude/` | 目錄下有 `skills/ rules/ hooks/ commands/ agents/ output-styles/` 六個子目錄 |
| 3 | skill 載入成功 | `/next` 列得出 skill 清單 |
| 4 | hook 生效 | 要求執行 `rm -rf` 時被擋下並說明原因 |
| 5 | MCP 設定檔存在 | `.mcp.json` 存在（內容可只留一個 server） |

## S1 問對問題

| # | 判準 | 怎麼驗 |
|---|---|---|
| 1 | 決策卡存在 | `decision-card.md` 存在且非空 |
| 2 | 現況量化 | 「現況」段有三個數字：誰做、一次多久、多久一次 |
| 3 | 成功條件可核對 | 至少 1 條能用 yes/no 回答（不含「品質好」「順暢」這類詞） |
| 4 | 邊界明確 | 「不做什麼」至少 2 條 |
| 5 | 分流有結論 | 分流結果不是「先別做」；若是，需附拆解後的新結論 |

## S2 定契約

| # | 判準 | 怎麼驗 |
|---|---|---|
| 1 | 七欄位齊全 | `docs/PRD.md` 的 Role / Goal / Inputs / Constraints / Output format / Success criteria / Examples 都非空 |
| 2 | 無 Model Rule | PRD 內找不到「請仔細」「請確保」「請不要遺漏」「一步一步」這類叮嚀 |
| 3 | 考卷筆數足夠 | `evals/evals.md` 測資 ≥ 10 筆 |
| 4 | 有邊界 case | 其中 ≥ 3 筆是空值 / 超長 / 格式錯誤 |
| 5 | 基線已記錄 | 考卷有「基線」欄且填了日期與通過率（數字多少都行） |

## 判準的設計原則（給改教材的人）

寫新判準時，逐條檢查：

- [ ] 能用 **yes / no** 回答嗎？（「PRD 寫得夠清楚」❌ / 「七欄位都非空」✅）
- [ ] **誰來判**？程式能判的就不要問人
- [ ] 驗證方式**寫得出具體指令或檔案路徑**嗎？
- [ ] 每站 **≤ 5 條**？超過表示這站塞太多
- [ ] 有沒有哪一條其實在測「態度」而不是「產出」？（那種一律刪掉）
