# Status report shape

The shape of `docs/test-status.md` — the blueprint's generated counterpart. The blueprint is what a human approved; this is what the machine observed. They are two files because their authors differ: a CI job writing into an approved plan overwrites the approval it exists to serve.

Regenerated by CI **after merge, never on a pull request**. A status file rebuilt per PR collides on the same lines in every branch and tells you nothing the build's own red or green already did.

```markdown
# 測試現況

> 由 CI 於 merge 後生成。手改會在下次 merge 被覆蓋。
> 生成於 <ISO 8601>／HEAD：<SHA>／對照藍圖核准：<日期>

## 承諾狀態

| 承諾 | 標題 | 靜態 | 單元 | 整合 | 驗收 | 最後更新 |
| --- | --- | --- | --- | --- | --- | --- |
| PR-AUTH-01 | 會員登入 | ✅ | ✅ | ⬜ 未實作 | ✅ 落後 23 commit | `4b17006` |
| PR-ORD-02 | 訂單付款一致性 | ✅ | ✅ | ❌ | ⬜ 未判 | `4b17006` |

## 未實作

| 承諾 | 缺的層 | 分級 |
| --- | --- | --- |
| PR-RPT-01 | 全部 | 存量豁免 |
| PR-ORD-03 | 整合 | 新增 — 擋 merge |

## 豁免現況

- 豁免中 N 條，本次減少 M 條。清單本體在 `docs/test-blueprint.md`，只減不增。
```

## Four values, and the third is why this file exists

- ✅ — ran green against this HEAD
- ❌ — ran red
- ⬜ **未實作** — nothing claims this promise. It never turns red, because it is not there.
- 🕐 — ran, but against an older build; the cell says how far behind

A red-green dashboard shows the first two and is blind to the third. **A test that was never written is indistinguishable from a passing one** on every signal CI emits — that blindness is the whole reason for this report.

## Layers stay separate

One cell per layer, never aggregated. Unit green with acceptance unimplemented, and all four green, are two different worlds; one combined light burns the difference away. The reader is a developer looking up a specific promise, not a wall display.

## Where each cell comes from

| 層 | 來源 |
| --- | --- |
| 靜態 | the CI static job's result |
| 單元・整合 | promise markers in the test report |
| 驗收 | **最近判定** in `docs/uat-cases.md`, plus the run it was judged against |

The acceptance cell carries **both** verdict and freshness. A verdict alone lies by omission: a `pass` from three months and twenty commits ago renders identically to one from this morning. Freshness is the distance from the judged run's commit to HEAD, which is why `/uat-cases` records the run and not just the verdict.

**未實作** is a set difference, not a judgment: the promise IDs in the blueprint's traceability table, minus every promise ID the sources above accounted for.

Promise IDs follow the project's own requirement numbering (`FR-REF-03`); the `PR-` in the examples above is `/to-spec`'s default for projects that had none, not a norm.

## What this file must never do

Restate the plan. The layer table, the seam list and the CI tiers live in the blueprint and are cited from here by reference. Two copies of a plan diverge, and the generated one always wins by being newer — which is how a machine's snapshot quietly replaces a human's decision.
