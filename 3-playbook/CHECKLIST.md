# AI 開發防呆檢核表

> 適合印出來貼在辦公室。每個角色只看自己那一欄。
> 每一項都是**可以檢查的動作**，不是口號。

---

## 📋 PM

**開工前**
- [ ] 痛點寫得出「誰、痛在哪、多常發生」
- [ ] 「這一版明確不做」至少 2 項
- [ ] 每條驗收條件都有具體數字或文字

**每天**
- [ ] 工程師回報 AI 誤解了規格 → 當天改規格
- [ ] 新決定寫進檔案，不是只講在會議或聊天室

**驗收時**
- [ ] 自己跑一次驗收指令，不聽轉述

---

## 🧭 SA

**開工前**
- [ ] 「誰負責什麼」表中，會讓人受傷的工作沒有交給 AI
- [ ] AI 的輸出有固定格式（schema），格式錯誤時有退路
- [ ] 每條驗收條件都找得到架構裡負責的元件

**每天**
- [ ] 改了架構 → 檢查需求文件要不要同步
- [ ] 新增套件的請求 → 由人決定，不是 AI

**每月**
- [ ] 讓 AI 比對規格與程式碼，列出不一致處，人判斷哪邊對

---

## 🔍 QA

**開工前**
- [ ] 每條驗收條件都有對應的測試
- [ ] AI 窮舉的邊界情境，每一個預期結果都經過人看過

**每天**
- [ ] 測試是綠的
- [ ] AI 修 bug 時沒有改到測試（看 `git diff`）

**換模型、改 prompt 時**
- [ ] 重跑 eval，準確率沒有掉到門檻以下

---

## 🛠️ 工程師

**每張票開工前**
- [ ] `/clear` 開新對話
- [ ] 用 `@` 給它票與相關規格
- [ ] 要它先說計畫，看過再讓它動手

**每張票結束前**
- [ ] 自己跑過測試，不是只聽它說
- [ ] `git diff --stat` 只動了這張票該動的檔案
- [ ] 沒有新增套件、沒有寫死的金鑰
- [ ] commit，訊息寫清楚為什麼

---

## 👔 主管

**導入時**
- [ ] 紅線（金鑰、刪資料、正式環境）有用機制擋，不只是寫在文件裡
- [ ] 團隊知道「AI 說完成」不等於完成

**每月**
- [ ] 看一次各專案的「AI 誤解紀錄」：同類錯誤是不是在減少
- [ ] 規格與程式碼的不一致數量，是不是在控制內
