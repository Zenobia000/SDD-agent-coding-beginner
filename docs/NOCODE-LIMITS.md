# no-code 能力邊界 —— PRD 產出時 AI 該怎麼提示你

> 對應 [`DEFINE.md`](../DEFINE.md) 第 4 站。這份文件不是要你自己先篩掉哪些想法，
> 是給第 4 站那段 PRD 產出 prompt 用的背景知識 —— **讓 AI 主動標記、你來決定**，
> 而不是你在還沒把話講完之前就自我審查。
> 平台差異看 [`PLATFORMS.md`](./PLATFORMS.md)；這份只講**不管哪一家 no-code AI 平台都系統性弱的能力**。

## 這份清單解決什麼問題

**盡量想，不要先自我審查** —— 種子簡報和第 3 站的歧義問答表，寫下你真正想要的完整版本，不用管 no-code 做不做得到。

但拿到 PRD 草稿的時候，如果裡面有功能其實 no-code MVP 做不完整，你要嘛在第 7 站才發現（貴），要嘛現在就知道、決定要不要先用簡化版驗證（便宜）。

**所以這件事該由 AI 在產 PRD 草稿的當下主動做**：標出可能做不完整的功能，附一個簡化版建議，問你要不要接受 —— **不是直接刪掉，也不是不提**。完整版本不會消失，會被記進 PRD 的「決策記錄」，留著給未來的你（或未來的 coding agent）。

這條線的產出本來就帶一點「前哨站」性質：no-code MVP 先幫你驗證問題是不是真的成立，成立的話，PRD 加決策記錄就是你之後要不要換成地端 coding agent（[`claude`](../../../tree/claude)、[`antigravity`](../../../tree/antigravity)）自己刻出完整版時最快的起點 —— 不用重新想一次。

## 六類 no-code MVP 通常做不完整的能力

不是特定平台的功能列表（那會過期），是**不會過期的能力分類**。AI 產 PRD 草稿時會用這個表檢查你的功能清單。

| # | 能力 | 為什麼 no-code MVP 通常做不完整 | 例子 |
|---|---|---|---|
| 1 | **複雜資料關聯** | 資料層通常是簡化的表格/文件儲存，撐不住多對多、巢狀階層、需要交易一致性的操作 | 「一張訂單拆成多個出貨批次，每批次對應不同倉庫扣庫存」 |
| 2 | **背景工作／排程** | 沒有常駐的伺服器幫你跑定時任務或非同步佇列 | 「每天凌晨自動抓匯率」「扣款前自動推播提醒」 |
| 3 | **需要 server-side 密鑰的第三方串接** | 密鑰要放在後端，個人開發者在 no-code 平台上通常拿不到、也管不好這一層 | 「串接銀行自動抓帳單」「串金流」 |
| 4 | **多使用者權限與即時同步** | 角色權限（RBAC）、多人即時協作需要的後端架構，no-code 平台通常沒做到這麼細 | 「主管審核完，員工端要立刻看到狀態變化」 |
| 5 | **複雜運算／決策邏輯** | 多步驟條件判斷、演算法、規則引擎，no-code 平台的邏輯編輯器撐不住太多分支 | 「依歷史使用行為算出個人化推薦分數」 |
| 6 | **檔案處理與轉檔** | 大檔案上傳、影像／文件轉檔、OCR 需要專門的處理管線 | 「上傳 PDF 帳單自動解析出金額」 |

## AI 該怎麼標，你該怎麼決定

第 4 站的 PRD 產出 prompt 會要求 AI：功能清單裡任何一條踩到上面六類，**不要刪掉、不要沉默略過**，而是原樣保留完整版描述，標上 `[no-code MVP 待簡化]`，並附一句建議的簡化版本。

拿到標記之後，你有三條路，跟第 4 站「留／刪／問」的收斂邏輯接在一起：

| 你的決定 | 怎麼處理 |
|---|---|
| **接受簡化版** | 簡化版寫進 PRD §4 範圍；完整版寫進 §7 決策記錄，備註「no-code MVP 先驗證簡化版，完整版留給地端 coding agent」 |
| **我要完整版，不要簡化** | 這條多半代表題目本身超出這輪 no-code MVP 能做的範圍 —— 不用現在放棄，先記進開放問題，走完這輪 POC 驗證了核心假設之後，直接換軌到 coding agent 線去做完整版 |
| **乾脆不要這個功能** | 進非範圍，理由寫「no-code MVP 做不完整，且非核心假設」 |

**被標 `[no-code MVP 待簡化]` 不代表這個功能不值得做**，只代表這一版 no-code MVP 做不完整。完整版被記錄下來，不是被丟掉。

## 常見的簡化模式

大部分踩到能力邊界的需求，把「自動化」換成「使用者自己動手」，通常就做得到。這是 AI 提建議版本時最常用的模式：

| 能力邊界 | 完整版（no-code MVP 通常做不完整） | 簡化版（no-code MVP 通常做得到） |
|---|---|---|
| 排程 | 系統自動定時執行 | 使用者手動按一個按鈕觸發 |
| 第三方串接 | 系統自動抓資料 | 使用者自己匯入／貼上資料 |
| 多使用者權限 | 完整角色權限系統 | 只有你自己一個使用者，沒有登入系統 |
| 複雜運算 | 多步驟演算法 | 簡單公式，攤在畫面上讓使用者自己看得懂邏輯 |
| 檔案處理 | 自動解析上傳檔案 | 使用者手動輸入關鍵欄位 |
| 背景通知 | 扣款前自動推播 | 打開時被動用顏色標示「這週內有扣款」 |
