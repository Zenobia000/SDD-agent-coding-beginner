## 六種的核心差異

| 資產 | 誰觸發 | 何時生效 | **能被違反嗎** | 適合放什麼 |
|---|---|---|---|---|
| **CLAUDE.md** | 自動 | 每次對話 | ✅ 約 70% | 專案慣例、角色、必讀清單 |
| **rule** | 由 CLAUDE.md 引用 | 每次對話 | ✅ 同上 | 硬約束的說明與理由 |
| **skill** | 打 `/x` 或 AI 判斷 | 需要時 | ✅ | 多步驟流程、有附件的程序 |
| **command** | 打 `/x` | 需要時 | ✅ | 單檔的固定動作 |
| **subagent** | AI 判斷要派 | 需要時 | ✅ | 要獨立 context 或獨立視角 |
| **hook** | **系統** | 特定事件 | ❌ **不能** | 不可逆操作的攔截、狀態注入、自動化 |

**最重要的是「能被違反嗎」那一欄。**

```
所有東西都是「請 AI 遵守」，只有 hook 是「AI 沒得選」。
    ↓
不可逆的事（刪資料、force push、外洩 secret）→ 一律用 hook
其他 → rule / skill 就好
```

## 通用鐵律（六種都適用）

### ① 一定要驗證它真的生效
**沒驗證過的資產等於不存在。** 每篇最後一節都是驗證方法，不要跳過。

### ② 改完要重開
skill、hook、output style、subagent **都在 session 啟動時載入**。
改完沒反應，九成是忘記重開。

### ③ 不要放 secret
這些檔案**跟著 git 走、團隊都看得到**。

### ④ 不要寫絕對路徑
`/Users/sunny/...` 換台機器就壞。用 `${CLAUDE_PROJECT_DIR}`。

### ⑤ 裝第三方的先讀原始碼
skill 和 hook 會被當指令執行。**那是別人的程式碼。**
