# 隨身檢核清單

**要把任務丟給 AI 之前**
- [ ] 這件事落在「鋸齒」的哪一面？寫得出 `check()` 嗎？
- [ ] 三條限制齊了嗎：一個檔案 / 一個評分標準 / 一個時間預算？

**寫 prompt 之前**
- [ ] 刪到只剩 CTCO 四格 + Business Rule 了嗎？「怕它出錯」的叮嚀清乾淨了嗎？
- [ ] spec 裡的「成功標準」能不能**直接拿去當考卷**？

**接它的輸出之前**
- [ ] 用的是三層保證的哪一層？能不能升到 Structured Outputs？
- [ ] 有沒有 `model_validate_json` 這道最後的閘？

**做 RAG 的時候**
- [ ] 有沒有兩階段（粗篩 + reranker）？metadata 過濾用了嗎？
- [ ] prompt 有沒有要求它「先列引用再作答」？
- [ ] 查不到的時候，它會不會老實說「資料中無相關內容」？

**放 agent 出去跑之前（五塊都要指得出來）**
- [ ] Tools：`max_depth` 多少？到頂怎麼停？
- [ ] Context：每步只放需要的，還是整包塞？
- [ ] Memory：什麼門檻會觸發壓縮？
- [ ] Guardrails：注入三層在嗎？參數是 `json.loads` 不是 `eval` 吧？
- [ ] Feedback：錯誤訊息（stack trace）有沒有回灌給它？

**說「我改好了」之前**
- [ ] 判準是二元的嗎？dataset 有 10 筆以上嗎？
- [ ] 有沒有拿**同一份** dataset 跑前後對照？
- [ ] 說得出修掉的是哪一個失敗模式嗎？

**上線 / 交付之前**
- [ ] 換掉任一家模型，還跑得動嗎？
- [ ] 信心不足的時候，它會不會自己升級（互審 / 轉人工）？
- [ ] 高風險動作有沒有人類核准？授權層級可驗證嗎？
- [ ] 換一個人照著文件做，他需不需要回頭問你？

# 金句集

- 你可以外包**思考**，不能外包**理解**。
- 邊界由人劃，試錯由 AI 跑，判斷由人收。
- AI 不穩是**物理特性**，不是你字沒下對。
- 用**流程**換穩定，不要指望**單次**。
- 廢話是模型必須服從的**雜訊**。
- 不要用 prompt 防漏欄位，要用 schema 讓漏欄位變成**不可能**。
- RAG 不是讓它更聰明，是**不必用記憶硬撐**。
- 可控性 **>** 自動化程度。
- 不是叫模型仔細一點，是把**驗證自動化**。
- 別把 agent 當寵物養 —— 卡住就殺掉，用日誌重啟。
- 別讓球員兼裁判。
- 驗證閘門 = 多 agent 系統的 `assert`。沒落成程式的地方，就是你靠運氣的地方。
- 沒有同一份 dataset 比較，不准說「改好了」。
- 難的不是任何一層，是**交接點**。
- 怎麼做變便宜，**做什麼變昂貴**。
- **AI 越強，能理解的人越值錢。**
