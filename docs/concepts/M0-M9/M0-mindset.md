# M0｜先換腦袋：你的角色變了

## 角色換位

| | 以前 | 現在 |
|---|---|---|
| 你是誰 | 親自把答案寫出來的人 | **設計一個環境，讓 AI 跑出對答案的人** |
| 你做什麼 | 動手寫 | 劃定邊界、決定給它看什麼、設計怎麼驗收 |

## Software 3.0：你在編輯的是「意圖」

- **1.0** = 人寫程式碼
- **2.0** = 訓練神經網路（調權重）
- **3.0** = 用**自然語言**下指令

也就是說：**程式碼變成了模型的「編譯結果」**。你講意圖，它產出程式碼。

## 巨齒狀智力（Jagged Intelligence）：AI 的能力像鋸齒，不是平滑的

白話講：AI 不是「整體有多聰明」，而是**有些事超強、有些事爛到不行，而且兩者就在隔壁**。

| AI 的表現 | 什麼任務 |
|---|---|
| **超強** ⬆ | 有標準答案、能驗證對錯的（數學、程式碼） |
| **弱又不穩** ⬇ | 常識、價值判斷、要看懂弦外之音的 |

最危險的是：它弱的時候**不會說自己不確定，會很有自信地講錯**。

> 所以「分辨這件事落在鋸齒的哪一面」，本身就是一種工程能力。

## 原生工作者的四層能力

| 能力 | 說明 | 後面哪一章教 |
|---|---|---|
| ① 意圖精確度 | 能把「我要什麼」講到沒有模糊空間 | M2 |
| ② 判斷力 | 能看出答案哪裡怪 | M6 |
| ③ 系統設計 | 能搭出讓 AI 穩定工作的環境 | M5 |
| ④ 持續校準 | 能用數字證明有沒有變好 | M7 |

## 你的護城河不是打字快，是品味

```
❌ 價值 = 你產出的程式碼量
✅ 價值 = 邊界品質 ＋ 驗證強度 ＋ 理解深度
```

> 「要做什麼」和「怎麼驗證」是最貴、也最不能外包的兩件事。

## 把 CoT / ToT / ReAct 當化石看

（CoT = 叫 AI「一步一步想」、ReAct = 叫它「想一下再行動」，都是早期的 prompt 技巧）

這些以前要你手寫的技巧，現在已經**內建進模型**了 —— 變成一個叫 `reasoning_effort`（要它想多深）的參數。

> 白話結論：**昨天要手寫的技巧，今天變內建功能。** 看到新技巧時，先想「這會不會下一版就變內建」。

## 三條乾淨限制：怎麼安心放手讓 AI 亂跑

講者示範用這三條，8 小時跑了 900+ 次實驗：

| 限制 | 白話 | 鎖住什麼 |
|---|---|---|
| ① 只准動一個檔案 | 別讓它到處亂改 | **範圍** |
| ② 一個評估標準 ★ | 「好不好」要能變成一個數字 | **目標** |
| ③ 一個時間預算 | 跑幾輪就停 | **成本** |

少任何一條，AI 就會開始亂跑發散。

**收斂迴圈長這樣（概念，不是要你抄 API）：**

```
重複 N 次（N = 你的預算上限）：
    1. 讀目前的檔案 + 上一輪拿幾分
    2. 讓模型改寫，產出候選版本
    3. 用你的評分函式打分
    4. 只保留分數最高的那個
```

**放手之後，人類只做三件事**：看分數曲線、抽查最好的那個、決定什麼時候收工。

## 任務分流表：這件事到底該不該丟給 AI

| 能不能用程式驗證？ | 做錯的代價 | 怎麼辦 |
|---|---|---|
| 可以 ✓ | 低 | **直接交給 AI** |
| 部分可以 | 高 | **人機協作** |
| 不行 ✗ | — | **人類把關** |

> 一句話判斷：**寫不出 `check()` 的任務，先別丟給模型。**
