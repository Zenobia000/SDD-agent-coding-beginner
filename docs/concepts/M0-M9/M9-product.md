# M9｜把系統變成產品（AX 與創業產品化）

> 到這裡技術都做完了。最後一關是：**這東西能不能活下去？**

## 可控的系統 ≠ 有護城河的產品

| | |
|---|---|
| **技術成就** | 可控 |
| **商業存活** | 護城河 |

殘酷的現實：**人人都能拼出同樣的助理 → 技術不再是差異化。**

## 現在呼叫你服務的，越來越多是 AI

```
使用者：「幫我搞定」
    ↓
  agent 去比較 A、B、C 三家服務商
    ↓
  它只看一件事：任務路徑順不順
    ↓
  選中 B
```

> **在不在那份「選擇清單」上，決定你還有沒有生意。**

## UX → AX：同一件事，優化對象變了

（**AX** = Agent Experience，把體驗做給 AI 用）

| 維度 | UX（給人看） | **AX（給 agent 用）** |
|---|---|---|
| 入口 | 好用的介面 | **可調用的 API** |
| 資料 | 好看的排版 | **乾淨的 schema** ★ |
| 任務路徑 | 少點幾下 | **少幾個步驟** ★ |
| 信任訊號 | 品牌、評價 | **可預期的輸出** |

## 全自動是陷阱，全人工是白做

```
低風險 ──── 自動執行 ────→ 事後查 log
                │
             風險線 ← 你要畫的就是這條
                │
高風險 ──── 人類核准 ────→ 授權層級必須可驗證
```

**授權矩陣**（別人看一眼就知道哪些能放手）：

| 任務卡片 | 動作描述 | 可逆？ | 風險 | 授權方式 | 對應 guardrail |
|---|---|---|---|---|---|
| … | … | ✓ | 低 | **自動** | … |
| … | … | ✗ | 高 | **人類核准** 🖐 | … |

## 把可控系統變成產品：四階段，一問一產物

| 階段 | **要先答對的問題** | 產出的東西 |
|---|---|---|
| **Idea** | 這個痛點是真的嗎？ | 可驗證假設 |
| **MVP** | 做什麼、**不做什麼**？ | **Scope Doc** |
| **Launch** | 怎麼穩定運轉？ | 營運 SOP |
| **Scale** | 為什麼別人離不開我？ | **護城河** |

## 成本趨近零，正是危險所在

因為做功能太便宜了，需求會無限蔓延（Scope Creep）。

> **Scope Doc 裡「不做什麼」那一欄，是你對抗衝動的主防線。**

## 護城河：別人為什麼換不掉你

| 護城河 | 為什麼難複製 |
|---|---|
| ① **深度 Depth** | 砸錢買不到 |
| ② **專有資料** | 補不齊 |
| ③ **工作流綁定** | 切換成本太高 |

## 怎麼做變便宜，做什麼變昂貴

```
便宜了：寫程式、寫文件、做圖  ← AI 幫你做
昂貴了：判斷什麼該存在／該刪除
        能證明你真的理解這個系統
```

> **可以外包思考，不能外包理解。**

## 一份不看你本人也能驗收的契約

| # | 欄位 |
|---|---|
| ① | 一句話定位 |
| ② | 可驗證假設 |
| ③ | 做什麼 |
| ④ | **不做什麼** ★ 主防線 |
| ⑤ | **成功長什麼樣** ★ 直接接 M7 的 eval |
| ⑥ | 安全審查 |

## 這關的驗收

給別人「可驗證假設 + Scope Doc + 授權矩陣」三份文件，**他不必回頭問你**就能做下去。

> **他會來問你 = 你的判斷還沒收斂。**
