# M7｜用考卷取代感覺（評估驅動開發 EDD）

> **EDD** = Evaluation-Driven Development。白話：**先有考卷，才有開發。**
> 一句話：**「我覺得變好了」不是工程。**

## 五個成熟度等級

```
L0 無評估 → L1 入門 → L2 專業 → L3 自動化 → L4 自動最佳化
```

一路上做的事只有一件：**把「判斷對錯」這件事，逐格從人腦搬到系統。**

## 放棄 1–10 分，改二元判斷

| | 問題 |
|---|---|
| ❌ 1–10 分 | **不可重現** —— 今天給 7 分，明天同一個東西給 5 分 |
| ✅ 對 / 錯 | **可以加總成比率** |

```
通過率 = 對的筆數 ÷ 總筆數
```

## 誰來當裁判？看答案的性質

| 答案性質 | 裁判 |
|---|---|
| 有標準答案 | **程式 assertion** ★ —— **能用程式判就別請 LLM** |
| 沒有標準答案 | LLM-as-judge（用模型當裁判，**後備手段**） |
| 有參考資料 | RAG 指標（見下） |

## RAG 最難評，四步推進

```
① 合成評估資料 → ② No RAG vs RAG 對照 → ③ RAGAS 四指標 → ④ 歸因下手
                      ↑ 沒有對照組，你證明不了 RAG 有貢獻
```

## RAGAS 四指標的價值在「歸因」

（RAGAS = 專門評 RAG 的一套指標）
它的用處不是給你一個總分，是**告訴你壞在檢索、還是壞在生成**：

| 指標 | 白話 | 壞了代表 |
|---|---|---|
| **Context Recall** | 該撈的都撈到了嗎 | 檢索漏了 |
| **Context Precision** | 撈回來的乾不乾淨 | 檢索太雜 |
| **Faithfulness** | 有沒有忠於撈回來的資料 | 生成在瞎掰 |
| **Answer Correctness** | 端到端對不對 | 最終結果 |

## 回饋迴圈：一個可以重複跑的閉環

```
跑評估 → 撈出失敗案例 → 把失敗「聚類」成幾種模式 → 針對性改進 → 同一份 dataset 再跑
   ↑                        ↑ 消滅一整類，不是一筆一筆救火        ↓
   └────────────── 比較分數，升了才保留 ─────────────────────┘
```

> **沒有拿同一份 dataset 比較，就不准說「改好了」。**

## 改進優先序：先便宜、後昂貴

| 順序 | 做法 | 成本 |
|---|---|---|
| ① | **改 system prompt** ★ 先試這裡 | 最低 |
| ② | 加 few-shot 範例 | 低 |
| ③ | 改檢索 | 中 |
| ④ | **微調（fine-tune）** —— 前三項到頂了才出手 | 最高 |

**每動一步，就回去跑同一份 dataset。**

## SFT vs RAG：什麼時候該微調

| 手段 | 白話 | 適合 |
|---|---|---|
| **RAG** | 注入**會變的事實** | 知識常常更新 |
| **SFT**（微調） | 內化**穩定的行為** | 語氣、格式、風格要很穩 |
| **SFT + RAG** ★ | 兩個一起 | **多數場景最佳** |

> 一句話記法：**知識常變 → RAG；行為要穩 → SFT。**

微調資料怎麼來：
```
PDF 取出每頁文字 → 每頁產一組 question/answer
    → 包成 messages 三角色（system / user / assistant）★ 訓練資料格式的核心
    → 寫成 training_data.jsonl → 微調後跟基底模型比差異
```

## 二元 rubric 怎麼寫（把模糊判準變成 yes/no）

```
① 拆成可觀察的條件
   「有禮貌」→「結尾有致歉或感謝」
② 用 AND / OR 接成可以核對的句子
③ 想幾個負例，確認擋得住
    ↓
裁判只回 { pass: true/false, reason: "..." }
```

> **每一條都要能用一句 yes/no 回答。**
> 「夠不夠專業」「是否夠詳細」這種 ❌ —— 不可核對。

## 人類審核介面：把「讀千段」壓成「點千次」

卡片上**只放做決定所需的最小資訊**：

```
┌─────────────────────────┐
│ 輸入          ……         │
│ AI 輸出       ……         │
│ 信心分數      0.42 ← 低分標紅，優先看 │
│ grounding 來源 ……        │
├─────────────────────────┤
│  [ ✓ 通過 ]  [ ✗ 退回 ]   │ ← 二元裁決
└─────────────────────────┘
```

## 這關的驗收

1. 改寫成二元判準
2. 建 **≥ 10 筆** dataset
3. 聚類失敗模式
4. 挑最便宜的那層改一次
5. 同一份 dataset 再跑

結果要能講成：**通過率 60% → 85%，而且說得出修掉了哪一個失敗模式。**
（「感覺比較順」❌）

> 串起來看：**M2 的 Success criteria → M7 的二元裁判 → L4 自動最佳化。**
> 好的 eval 就是自動最佳化的燃料。
