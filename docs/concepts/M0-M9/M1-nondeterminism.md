# M1｜先承認：AI 本來就不穩

## 先親眼看見它不受控

同一句話問三次，會得到三個不一樣的答案。

> **這是物理特性，不是你字沒下對。** 別再無止境地「調咒語」了。

## 一個 API 就是「吃訊息、吐文字」的函式

（Responses API 是 OpenAI 的統一介面）

這幾個參數，就是你手上的**旋鈕**：

| 參數 | 白話 |
|---|---|
| `input` | 你丟給它的對話內容 |
| `instructions` | 系統規則（整體要遵守什麼） |
| `max_output_tokens` | 最多能回多長 |
| `temperature` | 亂度旋鈕 |

> **token** = 模型把文字切成的最小單位。它不看「字」，看 token；計費和長度限制也都是算 token。

## 為什麼不穩？因為每個字都是「抽」出來的

模型每產出一個字，都是從一個機率分布裡抽一個。三個旋鈕在調這個抽法：

| 旋鈕 | 白話 |
|---|---|
| `temperature` | 分布要多尖銳。**低溫 = 專注穩定，高溫 = 發散多樣** |
| `top_p` | 只從累積機率前 X% 的候選裡抽 |
| `top_k` | 只從機率最高的 k 個裡抽 |

實測：`temperature=1.2` 跑十次，出現好幾種答案；`temperature=0` 跑十次，答案趨於一致。
但注意 —— **低溫也不保證每次一模一樣**。

## 解法：用「流程」換穩定，不要指望「單次」

這三步是**整堂課的縮影**：

1. **鎖死變因** —— 固定模型 + 固定 prompt + 低溫
2. **多跑幾次 + 找個評審挑最好的** —— 跑 10 次，用規則/程式檢查/另一個模型當評審，多數決或挑最可信 → **10 個候選收成 1 個穩定答案**
3. **用信心訊號過濾** —— 模型會吐出「它有多確定」的數字（logprobs），低於門檻就在程式層擋掉

## Token 就是錢

- context window（模型一次能看多少字）是**有限預算**，塞爆會直接報錯
- 計費 = 輸入 token + 輸出 token
- `max_output_tokens` 是你的**成本硬閘門**
- **廢話 = 花錢，而且還變成干擾模型的雜訊**

## 三家的「想多深」旋鈕

| 廠商 | 參數 |
|---|---|
| OpenAI | `reasoning_effort`（low / medium / high） |
| Claude | `thinking budget_tokens`（給它多少 token 去想） |
| Gemini | `thinking_config`（min / default / max） |

想越深、燒越多 token。但**它「想」的過程你看不到全貌 → 這就是對齊風險**（你不知道它為什麼得出這個結論）。

## 被擋下 ≠ 沒能力

文字、圖片、檔案現在都丟進同一個 `input` 陣列。
回傳時要看 `finish_reason`：

- `STOP` = 正常講完
- `SAFETY` = 被安全機制擋下

> 這兩個要分清楚 —— **被攔截不代表它做不到**，是被政策擋了。

## 這關的驗收

- 能展示「收斂前 vs 收斂後」的相異答案數量對比
- 說得出一個「鋸齒邊界」的真實例子（哪件事它突然翻車）
