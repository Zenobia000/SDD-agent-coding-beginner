# 人力政策：控制增量、保住品質底線

| | Shopify | Duolingo | Klarna |
|---|---|---|---|
| 做法 | 加人前先說明 AI 為什麼做不到 | 停用約聘做 AI 能做的事，考核看 AI 使用 | AI 客服宣稱抵 700 人，凍結招募 |
| 反應 | 反彈小，自然流失 | 強烈反彈，執行長兩度澄清 | 品質下降，執行長承認太看重成本 |
| 結果 | 人數穩定下降 | 產能大增，用戶成長放緩（因果未證實） | 改回保證找得到真人 |

**把目標訂成「人數持平、處理量上升」**，用自然流失調整人力；先裁人再驗證，是最貴的順序。

來源：TechCrunch 2025-04-07；Fortune 2025-08-18；Fortune 2025-05-09

# 數位員工：每個 agent 都要有身分、負責人和權限

| 上崗前要回答 | 為什麼 |
|---|---|
| 身分 | 不和員工共用帳號，出事查得到是誰 |
| 負責人 | 每個 agent 有一位對結果負責的人 |
| 權限 | 只給完成任務需要的權限；不可信輸入、敏感資料、對外動作三者最多同時碰兩個 |
| 紀錄 | 每個動作都留下紀錄 |
| 人工審核點 | 付款、對外承諾、刪除資料前由人確認 |

Replit 的 agent 刪掉正式資料庫，Amazon Q 擴充套件被植入刪除指令：兩起事故的共同原因都是權限給太多。

來源：OECD AI Incidents 2025-07；Meta Agents Rule of Two（Simon Willison 2025-11）

# 第一個 90 天：一個場景、一位負責人、一條基準線

| | 第 1–30 天 | 第 31–60 天 | 第 61–90 天 |
|---|---|---|---|
| 做什麼 | 盤點員工已經在用的 AI；訂內規；挑出第一個場景 | 重新設計那一個流程；量沒有 AI 時的基準線 | 上線、比對成效 |
| 交出什麼 | 內規初版、場景評分表 | 新流程圖、基準線數字、驗收標準 | 成效報告；擴大、調整或停掉的決定 |
| 誰負責 | 總經理指定一位負責人 | 負責人與第一線團隊 | 負責人向經營會議報告 |
