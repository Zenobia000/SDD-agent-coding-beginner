# 工具 5　數位員工上崗檢核表：五個問題答完才讓 agent 上線

<p class="lede">這份檢核表讓你在 AI agent 上線前，像替新員工辦到職一樣確認它的身分、負責人、權限、紀錄與審核點。每個 agent 上線前跑一次，權限或工具有變動時再跑一次。對應報告第 7 章〈數位員工〉。</p>

已經發生的 agent 事故，共同原因是權限給太多。Replit 的 agent 在程式凍結期間刪掉正式資料庫；Amazon Q 的 VS Code 擴充套件被塞進一段惡意指令，要 agent 清空使用者目錄並刪除雲端資源，而且帶著跳過確認的參數發布出去。[^t5-replit][^t5-amazonq] 數發部 2026 年的 AI 風險分類框架，也把「AI 自主代理的授權外行為」列為獨立的風險類別。[^t5-moda]

Agent 名稱：＜名稱＞　用途：＜一句話說明＞　檢核日期：＜日期＞　檢核人：＜姓名＞

## 一、身分：它是誰

- [ ] 有自己的帳號，不借用任何員工的帳號或個人 API 金鑰
- [ ] 帳號名稱看得出是 agent，例如 `agent-＜用途＞`，在系統紀錄裡和真人分得開
- [ ] 已登記到公司的 agent 清冊，寫明用途、上線日、版本
- [ ] 憑證放在公司的金鑰管理系統，有到期日，不寫在程式碼或設定檔裡

## 二、負責人：出事找誰

- [ ] 指定一位業務負責人，對 agent 的產出結果負責
- [ ] 指定一位技術負責人，負責權限、版本與停用
- [ ] 負責人離職或調動時，交接清單裡有這個 agent
- [ ] 出事時的聯絡方式與代理人寫在清冊上

## 三、權限：它能碰什麼

- [ ] 列出它能讀的資料與系統，每一項都寫得出為什麼需要
- [ ] 列出它能寫入、發送、刪除的對象，每一項都寫得出為什麼需要
- [ ] 預設只讀；寫入權限限定在特定資料夾、資料表或收件對象
- [ ] 沒有開啟一次允許所有工具、跳過人工確認的設定
- [ ] 碰不到正式環境的憑證；開發測試與正式環境分開
- [ ] 能在＜N 分鐘＞內停用帳號、撤銷權限，而且演練過一次

## 四、紀錄：事後查得到

- [ ] 記錄每一次輸入、呼叫的工具、讀寫的資料與輸出
- [ ] 紀錄保存＜N 個月＞，agent 本身無法修改或刪除
- [ ] 每＜週／月＞有人抽查紀錄，抽查結果有留存

## 五、人工審核點：哪些事要人點頭

- [ ] 列出必須由人確認才能執行的動作：刪除、付款、對外發送、變更權限、變更正式環境、＜其他＞
- [ ] 審核人看得到 agent 要做什麼、根據什麼，才按下確認
- [ ] 審核點寫進流程圖，不靠 agent 自己判斷要不要問人

## Rule of Two：不可信輸入、敏感資料、對外動作最多同時具備兩項

提示注入攻擊（把指令藏在信件、網頁、文件裡，讓 agent 照做）目前沒有可靠的防禦方法。Meta 在 2025 年 10 月提出 Agents Rule of Two：同一個 agent 在同一次執行中，下面三項最多只能同時具備兩項。[^t5-rule2] Microsoft 365 Copilot 的 EchoLeak 漏洞就是三項同時成立：攻擊者寄一封夾帶隱藏指令的信，Copilot 讀到之後就可能把 OneDrive、SharePoint、Teams 的資料外傳。[^t5-echoleak]

這個 agent 具備哪幾項？

- [ ] **處理不可信的輸入**：會讀外部信件、網頁、客戶上傳的檔案、第三方文件
- [ ] **存取敏感資料或系統**：能讀機密、個資、內部系統或正式環境
- [ ] **改變狀態或對外通訊**：能寄信、發訊息、呼叫外部 API、寫入或刪除資料

| 勾了幾項 | 判定 |
|---|---|
| 0–2 項 | 可以進入上線審核 |
| 3 項 | **不得上線。** 拆成兩個 agent，或在對外動作前加一道人工審核點，讓同一次執行裡最多只有兩項自動進行 |

## 上線後定期查品質、權限與異常行為

| 監控項目 | 頻率 | 負責人 |
|---|---|---|
| 抽查輸出品質，記錄錯誤與被人工退回的件數 | ＜每週＞ | 業務負責人 |
| 檢查實際使用的權限，沒用到的權限收回 | ＜每月＞ | 技術負責人 |
| 檢查異常行為：大量讀取、非上班時間操作、呼叫清單外的工具 | ＜每天，自動告警＞ | 技術負責人 |
| 模型、工具或權限有變動時重跑本檢核表 | 每次變動 | 技術負責人 |

## 符合任一項下架條件，先停用再調查

出現下列任一情況：

- [ ] 做出授權範圍外的動作，或試圖取得更多權限
- [ ] 被發現讀到不可信輸入裡的指令並照做
- [ ] 錯誤率或退回率連續＜N＞週高於上線時訂的門檻
- [ ] 業務負責人離職或調動，＜N＞天內沒有人接手
- [ ] 紀錄缺漏，無法還原它做過什麼

<div class="advice" markdown>
第一個 agent 從「只讀、只建議、人執行」開始。紀錄看了一個月沒有問題，再逐項開放寫入權限，每開一項就重跑一次本表。
</div>
