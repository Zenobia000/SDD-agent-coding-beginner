# 工具 4　效益衡量表：上線前先量基準線，品質和成本一起量

<p class="lede">這張表幫你在場景上線前定好要量什麼、怎麼量，上線後在固定的時間點回頭比對。在第一個 90 天的第 31–60 天、流程重新設計之前就要開始用。對應報告第 8 章〈衡量〉。</p>

BCG 在 2025 年訪問 1,803 位高階主管，60% 的企業沒有定義或追蹤任何 AI 相關的財務 KPI。[^t4-bcg] 多數試點量不出效益，問題出在沒有基準線，不一定是 AI 沒用。

## 基準線至少量一個完整業務週期，用上線後同一把尺

| 項目 | 做法 |
|---|---|
| **量多久** | 至少涵蓋一個完整的業務週期。有月結的流程量滿一個月；每天發生的流程至少量＜2–4＞週 |
| **量什麼** | 和上線後完全相同的指標、相同的定義、相同的資料來源。上線後才改定義，前後就不能比 |
| **誰量** | 優先從系統紀錄撈（處理時間、件數、退件數）。需要人工判斷品質時，由流程負責人以外的人抽樣評分 |
| **量多少件** | 抽樣評品質時，每期至少＜N＞件，抽樣方式前後一致 |
| **記在哪** | 下方的衡量表，基準線那一欄在上線前填完並由負責主管簽名 |

## 品質、效率、成本、採用四類指標，每類至少放一個

每個場景四類都要至少有一個指標。只量其中一類，最容易出現的就是只看成本。

| 類別 | 指標範例 | 資料來源 |
|---|---|---|
| **品質** | 錯誤率、被人工退回或改寫的比例、客訴件數、稽核抽查的缺失數 | 系統紀錄、抽樣評分 |
| **效率** | 每件處理時間、從收件到完成的週期時間、每人每天處理件數 | 系統時間戳記 |
| **成本** | 每件處理成本、AI 授權與用量費用、重工成本 | 財務、工具帳單 |
| **採用** | 每週實際使用人數、企業版工具占全部 AI 使用的比例、交給 AI 處理的件數占比 | 工具後台 |

## 領先指標決定要不要調整，落後指標決定要不要擴大

領先指標幾週內就看得到變化，用來決定要不要調整；落後指標要一季以上才穩定，用來決定要不要擴大。

| 層次 | 領先指標（週、月） | 落後指標（季、年） |
|---|---|---|
| 採用 | 啟用率、每週使用人數、企業版工具的使用占比 | — |
| 效率 | 每件處理時間、週期時間 | 單位產出成本、人均產出 |
| 品質 | 人工退回率、被抓到的錯誤件數 | 客訴、法律事件、重工成本 |
| 財務 | — | 可歸因於 AI 的營業利益、工具的總持有成本 |
| 風險 | 資料外洩防護攔截次數、未核准工具的數量 | 外洩事件數與損失 |

指標組合整理自 DX、McKinsey、BCG、DORA 等衡量框架。[^t4-framework]

| 類別 | 指標 | 定義與資料來源 | 基準線 | 第 30 天 | 第 90 天 | 第 180 天 | 目標 |
|---|---|---|---|---|---|---|---|
| 品質 | ＜例：人工退回率＞ | ＜退回件數 ÷ 總件數，系統紀錄＞ | | | | | |
| 效率 | ＜例：每件處理時間＞ | ＜收件到完成的中位數，系統時間戳記＞ | | | | | |
| 成本 | ＜例：每件處理成本＞ | ＜人力工時成本加工具費用 ÷ 件數＞ | | | | | |
| 採用 | ＜例：交給 AI 的件數占比＞ | ＜AI 處理件數 ÷ 總件數＞ | | | | | |

## 第 30、90、180 天各回頭看一次，每次都要做一個決定

| 時間點 | 主要看 | 要做的決定 |
|---|---|---|
| **第 30 天** | 採用與品質：有沒有人在用、品質有沒有掉到基準線以下 | 品質掉了先停下來修，不要等到第 90 天 |
| **第 90 天** | 效率與品質對照基準線 | 擴大、調整，或停掉。三個選項都是合格的結論 |
| **第 180 天** | 成本與財務，以及品質是否守住 | 決定是否複製到其他團隊，並把指標寫進部門 KPI。財務指標持續追到第 12 個月 |

## 只用自評、只量成本、沒有基準線，是最常見的三個錯誤

- **只用自評。** METR 讓 16 位資深工程師在 246 個真實任務上隨機決定能不能用 AI。他們事後覺得自己快了 20%，實測慢了 19%。[^t4-metr] 問卷問「有沒有變快」，會得到過度樂觀的答案，效率指標要從系統紀錄撈。
- **只量成本。** Klarna 曾宣稱 AI 客服抵得上 700 名全職人力，之後執行長承認成本被看得太重、品質因此下降，重新招募真人客服。[^t4-klarna] 品質指標要和成本指標同一天上線。
- **沒有基準線就上線。** 英國工作及退休金部的 Copilot 試用評估自己列出限制：資料是自陳，而且沒有試用前的基準線。[^t4-dwp] 補量基準線最晚要在上線前完成，上線後就回不去了。

<div class="advice" markdown>
上線前，請負責主管在基準線那一欄簽名。簽了名的數字，第 90 天才比得下去。
</div>
