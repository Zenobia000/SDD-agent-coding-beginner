# 啟動包寫作與圖表規範

> 寫報告、簡報、部門篇、工具之前先讀這一份；交稿前逐條自查。
> 規則擷取自管顧業的寫作經典，再套上桑尼資料科學的語氣規範。

---

## 1. 結構：金字塔原理（Barbara Minto）

- **先講結論。** 每份文件、每章、每節，第一句就是結論。理由放後面。
- **一個主旨，三到五條論點。** 主旨往下拆的論點要彼此不重疊、合起來不遺漏（MECE）。超過五條，代表還沒想清楚哪些可以合併。
- **開場用 SCQA。** 情境（大家都同意的事）→ 衝突（出了什麼問題）→ 問題（所以要回答什麼）→ 答案（本文的主旨）。
- **同一層不混用兩種邏輯。** 要嘛是演繹（因為 A、而且 B，所以 C），要嘛是歸納（A、B、C 是同一類事情）。
- **上下層是問答關係。** 讀者看到一個論點會問「為什麼？」或「怎麼做？」，下一層就要回答那個問題。

## 2. 標題：行動標題

- **每個章節標題、每頁簡報標題都是一句完整的結論**，最多兩行。
  - ✗ 主題詞：「資料問題」
  - ✓ 行動標題：「AI 拿不到工作需要的脈絡，示範時很聰明，接上真實資料就失準」
- **storyline 測試**：只讀所有標題，要能讀成一份完整的執行摘要。讀不通，就是結構有問題，不是文字有問題。
- **一頁一件事。** 一頁或一節塞了兩個結論，就拆開。
- **例外**：第四部部門篇用固定的六段小標（現況證據、先做這一件、不能交給 AI 的決策、加 AI 還是重建、雷區、該量的三個指標），方便跨部門對照；每段第一句仍然是結論。工具的條文編號（第 N 條）也照範本格式。
- **所以呢？** 每一段寫完問一次「所以呢？」，答不出對讀者有什麼影響，就刪掉或改寫。

## 3. 圖表：圖表即結論（Gene Zelazny《Say It With Charts》）

- **圖表標題就是結論**，不是「各部門 AI 使用率」，而是「後勤部門的回報最高，預算卻多半花在前台」。
- **先決定要比較什麼，再選圖。**

| 要比較的是 | 用這種圖 |
|---|---|
| 成分（整體裡各占多少） | 堆疊橫條 |
| 項目排序（誰大誰小） | 橫條 |
| 時間變化 | 柱狀或折線 |
| 分佈 | 直方圖 |
| 相關（兩個變數的關係） | 散佈圖或成對橫條 |
| 選項定位 | 2×2 矩陣 |
| 階段演進 | 階梯 |

- **每張圖表都有**：編號（圖表 3.2）、行動標題、單位、資料來源與樣本、註記（例如「受訪者自述」）。
- **不同調查的數字不放在同一根軸上比**，除非註明母體不同。

## 4. 證據：權威來自分母和出處

- 每個數字附註腳：機構、發表日期、樣本與母體。
- 證據分四級，寫法不同：

| 等級 | 例 | 寫法 |
|---|---|---|
| 研究（同儕審查、隨機對照實驗） | 客服 RCT、METR | 可以直接下結論 |
| 顧問與研究機構調查 | McKinsey、BCG、MIT CISR | 寫明是調查，附樣本 |
| 廠商數據 | Microsoft、Salesforce | 註明「廠商數據」 |
| 個案與媒體報導 | Klarna、Air Canada | 當例子用，不當通則 |

- 研究檔標 ⚠️ 的數字，補查前不准進正文。
- **常見誤用不准出現**：「95% 的 AI 專案失敗」（MIT NANDA 的分母混用、樣本 52 個組織）。要引用，就連同限制一起寫。

## 5. 權威感：判斷要明確

- **給建議，排順序，說不要做什麼。** 讀者付錢買的是判斷，不是資訊整理。
- **框架用桑尼自己的名字**：四根因、五個決策、四個階段、場景四問。每個框架都要能畫成一張圖。
- **不能編造案例。** 權威口吻建立在真實證據上。公開個案照出處寫；作者的現場經驗由作者提供，原稿用【桑尼現場：待補】標出。

## 6. 語氣：桑尼資料科學語氣規範

依 `sunnedatascience/docs/specs/12_editorial_voice_guide.md`：

- 中性命題，具體動詞：做、改、拆、選、量、卡住。
- 少用「賦能、打造、驅動轉型、建立價值」。
- 不連用「不是 A，而是 B」；不連用「從 A 到 B」。
- 不湊三段式對仗；不寫口號；一段只處理一件事。
- 句子需要冒號、破折號、成對反義詞才成立，先改成正常中文。
- 拿掉品牌名後，任何一家 AI 公司都能直接用的句子，就太空泛，刪掉或補具體內容。
- 稱呼讀者用「你」；不販賣焦慮，不寫「再不做就來不及」。
- CTA 直接寫下一個動作：「談企業合作 →」。
