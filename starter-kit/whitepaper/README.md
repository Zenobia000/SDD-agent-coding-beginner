# 補充教材：企業常見系統的 AI 開發思考

> 請假系統只是起點。這裡用同一套思考框架，拆解七個企業內部常見的系統。
> 結訓後挑一個跟你工作最接近的，當作回公司的第一個練習題目。

---

## 七個系統一覽

| 系統 | 部門 | 難度 | AI 最有價值的地方 | 最不能交給 AI 的事 |
|---|---|---|---|---|
| [差勤系統](./attendance.md) | 人資 | ⭐ | 自然語言請假、異常出勤摘要 | 工時與加班費計算 |
| [請款系統](./expense-claim.md) | 財務 | ⭐⭐ | 發票辨識、費用分類 | 金額核對、核准 |
| [客服工單](./support-ticket.md) | 客服 | ⭐⭐ | 分類、摘要、回覆草稿 | 退款、賠償承諾 |
| [報價單系統](./quotation.md) | 業務 | ⭐⭐ | 從需求描述挑品項、草擬說明 | 價格、折扣、毛利 |
| [供應商比價](./vendor-comparison.md) | 採購 | ⭐⭐⭐ | 把格式各異的報價單整理成同一張表 | 選商決策 |
| [庫存系統](./inventory.md) | 營運 | ⭐⭐⭐ | 異常偵測、補貨建議的說明 | 庫存數量本身 |
| [活動成效看板](./marketing-dashboard.md) | 行銷 | ⭐⭐⭐ | 用白話問數據、自動寫週報 | 指標的定義與計算 |

難度看的是**資料的正確性要求**與**整合的外部系統數量**，不是程式碼量。

---

## 共同的思考框架

每一份都用同樣的六段，和 2 天課程的流程對應：

| 段落 | 回答什麼 | 對應課程 |
|---|---|---|
| 需求重點 | 核心 User Story，以及最常被漏掉的需求 | D1 PRD、SRS |
| 流程 | 誰、在什麼時候、做什麼 | D1 PRD 的 user flow |
| 架構 | 前端、後端、資料、外部整合 | D1 SAD、SDS |
| AI 在這裡 | 哪些交給 AI、哪些一定要程式碼或人 | D1 單元 5「誰負責什麼」 |
| 常見坑 | 上線後才會發現的問題 | D1 Test Plan、D2 I2–I4 |
| 第一張垂直切片 | 從哪裡開始做 | D2 I1 |

---

## 七個系統共通的三條規則

讀完七份你會發現，答案一再重複：

1. **錢、數量、時間的計算，永遠是程式碼。** 金額、庫存、工時，同樣的輸入必須永遠得到同樣的答案。LLM 做不到這件事。
2. **AI 產出的是草稿，送出的是人。** 報價單、回覆客戶、選商建議都一樣。系統要讓「人確認」這一步省力，而不是讓它消失。
3. **原始資料要留著。** 員工打的那句話、客戶的原始來信、供應商的原始報價檔。AI 解析錯了，你要有東西可以回頭查。

## 怎麼用這份教材

**自學**：挑一個系統，從模板 repo [`agent-skills-starter`](https://github.com/Zenobia000/agent-skills-starter) 開一個 repo，照 2 天課程的流程走一次：六份規格 → 疊代拆票 → 做第一條垂直切片。模板在上課 repo 的 [`templates/`](https://github.com/Zenobia000/leavebot-bootcamp/tree/main/templates)。

**企業內訓**：講師可以用這七個系統替換 LeaveBot，當作不同部門學員的題目。每一份都標了難度，⭐ 的適合當 2 天主線，⭐⭐⭐ 的適合結訓後的進階專題。

> 這些文件給的是**思考方向**，不是規格。每家公司的流程不同，你們的需求要自己問出來 —— 這正是 Day 1 在練的事。
