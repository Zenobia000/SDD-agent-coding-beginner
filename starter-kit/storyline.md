## 主旨

**讓 AI 從員工的個人工具，變成企業看得見、量得到的工作成果：做對五個決策，照四個階段推進，用 90 天驗證一個值得擴大的場景。**

## 開場（SCQA）

| | |
|---|---|
| 情境 | AI 的能力每幾個月就往前一步，近九成的組織已經在用 |
| 衝突 | 讓營業利益多出 5% 以上的只有約 6%；台灣員工 84% 在用，把 AI 接進核心流程的企業只有 6.6% |
| 問題 | 企業要怎麼把「員工個人在用」變成「公司拿得到回報」？ |
| 答案 | 主旨 |

---

## 00　執行摘要

五條關鍵訊息，各配一個數字：

1. 落差是真的：近九成在用，約 6% 有感。
2. 卡住的是組織：七成困難在人與流程，模型只占三成。
3. 有回報的企業重新設計流程的比例，約是其他企業的 3 倍。
4. 五個決策決定成敗：人力政策、場景組合、護欄、數位員工、衡量。
5. 照四個階段推進，第一個 90 天要交出一個量得到成效的場景。

## 第一部　判斷

### 第 1 章　AI 的能力已經到位，多數企業的帳上還看不到回報

| 節 | 行動標題 | 圖表 |
|---|---|---|
| 1.1 | 近九成組織在用 AI，讓營業利益多出 5% 以上的約只有 6% | **圖表 1.1** 階梯：經常使用 88% → 高績效者 6%。McKinsey 2025 🔸 |
| 1.2 | 台灣的落差更大：員工早就在用，公司還沒接手 | **圖表 1.2** 橫條：知識工作者在用 84%（Microsoft 2024）、使用在管控外 61.8%、整合進核心流程 6.6%（AIF 2026）✅。註明三者母體不同 |
| 1.3 | 有硬證據的效益集中在量大、有標準答案的工作，新手受益最多 | **圖表 1.3** 柱狀：客服每小時解決件數，平均 +14%、新手 +34%、資深約 0。Brynjolfsson 等，QJE 2025，5,179 人 ✅ |
| 1.4 | AI 的能力邊界參差不齊，用在邊界外反而更容易出錯 | **圖表 1.4** 柱狀：邊界外任務答對率，無 AI 84.5% → 有 AI 70.6% → 有 AI 加訓練 60%。BCG × 哈佛，758 人 ✅ |
| 1.5 | 感覺變快不等於真的變快，沒有基準線的試點會誤判成效 | **圖表 1.5** 成對橫條：自覺 +20%、實測 −19%。METR 2025，16 人、246 項任務 ✅ |
| 1.6 | 落差會累積：停在試點階段的企業，財務表現已經落後同業 | **圖表 1.6** 柱狀：MIT CISR 四階段的營收成長相對產業平均 −12.6／−3.5／+11.3／+17.1 個百分點，721 家 ✅ |

## 第二部　五個決策

### 第 4 章　決策一 人力政策：控制增量、保住品質底線，比削減人力更快拿到回報

| 節 | 行動標題 | 圖表 |
|---|---|---|
| 4.1 | 衝擊先落在新鮮人的招募，資深員工目前還沒有缺口 | **圖表 4.1** Stanford Canaries 年齡別就業變化 ⬜（各版本數字要對齊後才放數字） |
| 4.2 | 先裁人再驗證是最貴的順序：澳洲聯邦銀行撤回裁員，Klarna 改回人機雙軌 | 個案側欄 ✅；Gartner 預測一半的客服縮編計畫會放棄 🔸 |
| 4.3 | 把目標訂成「人數持平、處理量上升」，再用自然流失調整人力 | Shopify 員工數變化（年報轉述）🔸 |
| 4.4 | 少招新人會斷掉人才梯隊，新人的學習方式要重新設計 | **圖表 4.4** 柱狀：學新技術時全交給 AI 的人理解測驗 < 40%，邊用邊追問的人 ≥ 65%。Anthropic RCT，52 人 ✅ |
| 4.5 | 高層、中階主管、員工、新鮮人各有一件最該先做的事 | **圖表 4.5** 角色對照表。依據：AI 成效 67% 取決於組織（Microsoft 2026）✅ |

### 第 5 章　決策二 場景組合：先做量大、有標準答案、量得到的工作，少做幾個、做深

| 節 | 行動標題 | 圖表 |
|---|---|---|
| 5.1 | 預算多半花在看得見的前台，回報最高的卻是後勤 | MIT NANDA（受訪者自述，限制要寫明）🔸 |
| 5.2 | 用四個問題挑第一個場景：量大不大、有沒有標準答案、能不能量、錯了代價多大 | **圖表 5.2** 2×2：「量與標準化程度」×「出錯代價」，標出先做、謹慎做、暫緩、別做 |
| 5.3 | 台灣做出成效的企業，都從資料已經在的單點開始，先數位化再談 AI | **圖表 5.3** 對照表：全家、統一超商、宜展、隴鈦、滿記（企業自述）✅ |
| 5.4 | 能買就不要自建，但要求廠商貼合你的流程、能從回饋學習 | 外購上線率約 67% vs 自建約 33%（自述，可能有混淆）🔸 |
| 5.5 | 每個部門都有一個可以先做的場景（見第四部） | 指向部門篇 |

### 第 6 章　決策三 護欄：先給員工好用的企業版工具，再談禁止

| 節 | 行動標題 | 圖表 |
|---|---|---|
| 6.1 | 禁止只會把使用推到個人帳號，風險反而看不見 | **圖表 6.1** 橫條：貼資料到生成式 AI 的行為發生在個人帳號 82%（LayerX，廠商遙測）✅；影子 AI 相關外洩每起多約 67 萬美元（IBM 2025）✅ |
| 6.2 | AI 對外說的話就是公司說的話，法院已經這樣判 | 個案：Air Canada；處理 AI 捏造引用的法院判決 2025 年底 712 件、2026 年 6 月約 1,600 件 ✅ |
| 6.3 | 台灣法規正處在空窗期，現在正是先訂內規的時候 | **圖表 6.3** 時間軸：AI 基本法 2026-01-14 施行（無罰則）→ 數發部風險分類框架 2026-07-07 → 各部會產業規範 2028-01 前 ✅ |
| 6.4 | 用資料分級和人工審核點控制風險，比全面禁止有效 | **圖表 6.4** 資料分級 × 可用工具矩陣（桑尼框架） |

### 第 7 章　決策四 數位員工：AI agent 要像員工一樣有身分、負責人和權限

| 節 | 行動標題 | 圖表 |
|---|---|---|
| 7.1 | agent 已經出過真實事故，原因都是權限給太多 | 個案：Replit 刪除正式資料庫、Amazon Q 擴充套件、EchoLeak ✅ |
| 7.2 | 提示注入攻擊目前沒有可靠解法，只能從架構上限制 agent 能做的事 | **圖表 7.2** 三圈圖：不可信輸入、敏感資料、對外動作，同一個 agent 最多只碰兩個（Meta Agents Rule of Two）✅ |
| 7.3 | agent 上線前要回答五個問題：身分、負責人、權限、紀錄、人工審核點 | 對應工具：數位員工上崗檢核表 |
| 7.4 | 企業 agent 平台正在起量，市場上也充斥換皮產品，採購要會驗收 | Agentforce 付費客戶約 6%（二手）🔸；Gartner：數千家廠商約 130 家是真的 🔸 |

### 第 8 章　決策五 衡量：先量基準線，品質和成本一起量

| 節 | 行動標題 | 圖表 |
|---|---|---|
| 8.1 | 多數企業量不出效益，因為沒有基準線，也沒有財務指標 | **圖表 8.1** 60% 沒有定義任何 AI 財務 KPI。BCG 2025，1,803 位高階主管 ✅ |
| 8.2 | 三個月看使用與品質，十二個月看財務，兩種指標要搭配 | **圖表 8.2** 領先／落後指標對照表 ✅ |
| 8.3 | 只量成本會翻車，品質指標要和成本指標一起上線 | Klarna 個案 ✅ |
| 8.4 | 上線前先講好「怎樣算做到」，把驗收標準寫成可以自動檢查的測試 | 桑尼觀點：與 SDD 實戰營的方法接軌 |

## 第四部　部門與系統（每篇 3–4 頁）

每篇固定六段：現況證據、先做哪一件、不能交給 AI 的決策、加 AI 還是重建、雷區、該量的三個指標。

| 篇 | 行動標題 |
|---|---|
| 客服 | 客服是證據最硬的場景，目標放在處理量上升、保留真人選項 |
| 財務 | 請款與應付帳款回報最高，但 AI 生成的假收據已經逼稽核改成全查 |
| 人資 | 員工問答可以先做，招募篩選是法律雷區 |
| 業務 | 業務的公開成效多半是廠商說法，先從準備客戶資料這種內部工作做起 |
| 行銷 | 內容產量最容易提升，品牌與法遵審核要留在人身上 |
| 採購 | 比價與合約摘要可以先做，供應商選擇的決定權留在人 |
| 營運與庫存 | 需求預測與訂貨有台灣成功案例，前提是資料已經數位化 |
| 法務 | 契約初審省時間，對外的法律意見不能交給 AI |
| IT 與資安 | 服務台是最快見效的場景，也是 agent 權限最該管的地方 |
| 管理報表 | 用自然語言查報表，沒有先定義指標與資料欄位就不能上線 |
