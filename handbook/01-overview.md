# 兩天課程總覽

每天09:00–17:30，休息10:30–10:45、12:30–13:30、15:00–15:15，淨授課7小時。

## D1：Vibe Coding 到 PRD
在獨立D1資料夾，體驗網站首屏臨摹、塔羅抽牌、捲動動畫；每題6分鐘製作加2分鐘操作，是預算而非完成保證。選一題實作，補上下文比較，再把已確認需求寫成PRD草稿。第一天不要求LeaveBot規格、Archify或完整SDD文件。

| 時間 | 單元 | 產出 |
|---|---|---|
| 09:00–09:45 | 1 認識Coding Agent | 看到讀檔、產出與操作 |
| 09:45–10:30 | 2 Claude Code／Codex基本操作 | 獨立練習資料夾 |
| 10:45–12:30 | 3 三種吸睛Demo | 能說出各題觀察的能力 |
| 13:30–14:15 | 4 一次提示做作品 | 保留第一版與失敗紀錄 |
| 14:15–15:00 | 5 補上下文比較 | 同題兩版差異 |
| 15:15–16:30 | 6 操作驗收與修一個問題 | 通過項目、介入次數、修復證據 |
| 16:30–17:30 | 7 收斂PRD | 三條以上驗收條件與待決事項 |

## D2：SDD表單請假實作
換共同題目LeaveBot，用相同需求方法走到設計、測試與交付。技術固定為FastAPI提供靜態頁、SQLite、pytest；主線沒有LLM呼叫。

| 時間 | 單元 | 卡 |
|---|---|---|
| 09:00–09:45 | 8 從 D1 體驗接到 LeaveBot：確認問題與範圍 | A |
| 09:45–10:30 | 9 把共識寫成 PRD 與 SRS | B、C |
| 10:45–11:30 | 10 Archify 流程檢查與最小系統設計 | D、E |
| 11:30–12:30 | 11 人定預期結果，選案例再拆兩張票 | F、G |
| 13:30–15:00 | 12 從空白骨架到一條可驗收的表單功能 | H |
| 15:15–16:30 | 13 重現錯誤、修復，再走一次需求變更 | I、J |
| 16:30–17:30 | 14 操作驗收與交付 | K |

## 小組分工
規格軌決定範圍、審驗收與預期結果；工程軌操作Agent、跑測試與看diff。兩軌一起確認第一個紅燈、一起操作成品。輪流操作，不把不會寫程式的人留在旁邊看。

## 完成標準
選員工、填表、後端驗證、SQLite存檔、我的假單顯示pending，且自動化與人工驗收有證據。主管核准、額度、人數提醒、LLM解析與eval為延伸。只fork學生main即可，checkpoint從講師upstream取得。

## 文件與方法
六份固定路徑是本課選擇；每份只寫當前必要內容，通用skills不固定文件數量或票數。每張卡指定資料、產出與完成條件。文件與介面衝突時先問人，不讓Agent自行選邊。
