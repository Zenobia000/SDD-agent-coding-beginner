# 講師手冊：2 天實戰營

> 給講師。學員教材在 [`curriculum/1-bootcamp/`](../1-bootcamp/)。這一份管的是**節奏、檢查點、保底版本與帶課失誤**。

---

## 最重要的一件事

**這門課的價值在「人做決定」的那些時刻。** 教材給了模板、範例、提示詞，但每個單元都有一個決定只能由學員做：要不要做、做到哪、怎樣算過。

學員卡住時，**縮小問題，不要直接給答案**：

| 學員說 | 不要回 | 要回 |
|---|---|---|
| 「這樣算做完了嗎？」 | 「算」 | 「你的通過訊號跑起來是什麼？`trace.py` 怎麼說？」 |
| 「AI 說可以了」 | 「好」 | 「它跑過了嗎？輸出貼給我看」 |
| 「颱風假要怎麼算？」 | 給一個規則 | 「你們公司怎麼算？不知道的話，寫進待決事項」 |
| 「準確率 80% 夠嗎？」 | 「夠」或「不夠」 | 「錯的 20% 會發生什麼事？有退路嗎？你們 Test Plan 怎麼寫的？」 |

**例外**：D2 的保底版本。疊代落後時，給保底不是給答案，是讓學員能繼續練下一個疊代。

## 開課前必做

| 時間 | 項目 |
|---|---|
| 開課前 2 週 | 寄出 [`0-setup/`](../0-setup/) 檢核表，要求學員回報第 4 步（預熱）與第 5 步的結果 |
| 開課前 1 週 | 追蹤沒回報的人。**環境沒好的人，D1 上午會拖住整組；D2 早上會拖住整個疊代** |
| 開課前 1 週 | 自己用乾淨的機器，Claude Code 與 Codex **各**走一次 D1 單元 1 與 D2 的 I0 |
| 開課前 1 週 | **準備保底 repo**（見下）。同時是彩排：記下每個疊代實際花多久 |
| 開課前 3 天 | 確認 [`leavebot-bootcamp`](https://github.com/Zenobia000/leavebot-bootcamp) `bash scripts/check.sh` 全綠；`STACK.md` 的版本仍然裝得起來 |
| 開課前 1 天 | 依報名資料分組，**確保每組至少有一位規格軌、一位工程軌** |
| 開課當天 | 準備一台能跑 `LLM_PROVIDER=claude-cli` 的示範機，給只有 Codex 訂閱的組跑 I4 |

## 保底 repo：怎麼準備

**目的**：D2 是五個串起來的疊代。一組卡在 I1，後面四個疊代就全部看不到。保底版本讓落後的組能從下一個疊代的起點繼續。

1. 建一個 **private** repo（例：`leavebot-reference`），從 `leavebot-bootcamp` 開始。
2. 自己照 D1 走一次，產出六份文件與 I0–I4 五張票。
3. 照 D2 一個疊代一個疊代做，每個疊代結束打 tag：`i0`、`i1`、`i2`、`i3`、`i4`。
4. 每個疊代記下實際耗時。**任何一段超過課表時長，就回頭縮 `LEAVEBOT.md` 的 MVP 範圍，不是加時間。**

**不要公開這個 repo。** 學員看到完整答案，D1 的規格就會變成照抄。

**怎麼發**：落後的組先把自己的進度 commit 到 `wip/` 分支，再從保底 repo 拿上一個疊代的 tag 接著做。課後請他們比對兩者的差異 —— 差在哪裡，通常就是哪一份文件沒寫清楚。

## 檢查點：怎麼放行

| 檢查點 | 看什麼 | 沒過怎麼辦 |
|---|---|---|
| D1 單元 3 結束 | PRD 的 AC 有沒有失敗路徑、有沒有「合理」「正確」 | 當場挑一條全班一起改 |
| D1 結束 | `trace.py`：V 的左邊完整；I1 那張票夠薄 | I1 太厚就當場帶他們削薄 |
| D2 每個疊代結束 | `trace.py` 的缺口有沒有變少；demo 走不走得通 | 過了 15 分鐘還沒過 → 發保底 |
| D2 收尾 | `trace.py --strict` | 不要求全綠，要求**念得出缺口** |

## 每天的高峰時刻

| 時刻 | 為什麼不能省 | 怎麼帶 |
|---|---|---|
| D1 單元 1：`git add -A` 被擋 | 學員第一次看到「規則」和「做不到」的差別 | 讓他們自己找出是哪個檔案擋的，不要直接說 |
| D1 單元 5：「誰負責什麼」那張表 | 整個系統的安全與正確性都建立在這張表上 | 一定會有組想把「算剩餘天數」交給 AI。讓他們說理由，再問：「算錯一次會發生什麼？」 |
| D2 I2：破壞測試 | 學員第一次看見測試的價值，而不只是聽說 | 有組的測試沒抓到時，**公開表揚**。那是最有價值的發現 |
| D2 I4：prompt injection | 「叫 AI 不要聽」行不通，這件事要親眼看到 | 先讓大家試著用 prompt 擋，失敗之後再回到 D1 單元 5 那張表 |

## 分組與兩軌

- 每組 3–4 人，至少一位規格軌、一位工程軌。
- **規格軌的人要親手跑驗收指令。** 不寫程式不代表不能按 Enter。
- 工程軌的人不准替規格軌決定需求。發現規格不清楚時，回頭改 `docs/`，不要自己猜，也不要讓 AI 猜。

**常見失衡**：工程軌太強，規格軌變成旁觀者。看到這種情況，請工程軌暫停打字，改由規格軌口述給 AI。

## 常見的帶課失誤

| 失誤 | 後果 |
|---|---|
| 讓學員原封不動貼提示詞 | 學到打字，學不到判斷。每次都要他們先改成自己的版本 |
| 讓學員照抄 `examples/it-asset/` | 範例是看深度用的。抄了之後 LeaveBot 的規格會長出設備借用的欄位 |
| 幫學員定義「做完」 | 學員回公司後，沒有你在旁邊就不知道怎麼驗收 |
| D2 讓落後的組硬撐 | 卡在 I1 的組看不到 I4，而 I4 是這門課最有價值的一段。15 分鐘沒過就發保底 |
| 允許 agent 換技術棧 | 一組換了框架，整天都在除錯環境。`STACK.md` 是紅線 |
| D2 只 demo 成功的部分 | 錯過最有價值的內容：失敗的地方與學到的事 |
