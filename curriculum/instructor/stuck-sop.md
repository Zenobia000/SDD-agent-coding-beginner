# 卡關處理 SOP

## 結論卡

| | |
|---|---|
| **鐵律** | 卡超過 **10 分鐘**就介入，不要等他舉手 |
| **最重要的一條** | **不要幫學員寫 code** |
| **介入順序** | 縮小問題 → 給提示 → 給答案 + 解釋為什麼會卡 |
| **保底** | 讓他改用參照專案跟跑，不要卡住整段 |
| **下一步** | 助教開課前把「常見卡點」那節看完 |

---

## 一、介入的四步

**不要一步到位給答案。** 照這個順序：

### ① 指出他現在的狀態（30 秒）
```
「你已經有 PRD 了，缺的是考卷。」
```
很多時候學員只是不知道自己走到哪。

### ② 縮小問題（1 分鐘）
```
「先別管整份考卷。只看第一條判準——它能用 yes 或 no 回答嗎？」
```
把「我不會」縮成一個他答得出來的小問題。

### ③ 給提示，不給答案（2 分鐘）
```
「你寫的是『摘要品質好』。如果我給你兩份摘要，你會怎麼比？」
```

### ④ 還是卡 → 給答案 + **解釋為什麼會卡**（3 分鐘）
```
「這樣寫：『字數 ≤ 原文 20%』。
 你剛才卡住是因為『品質』是一個結果，不是一個可以量的東西。
 遇到形容詞就要問自己：這個形容詞背後我實際在看什麼？」
```

**第 ④ 步的後半句最重要。** 沒有它，下次他還是會卡在同一個地方。

---

## 二、絕對不要做的三件事

| ❌ 不要 | 為什麼 | ✅ 改成 |
|---|---|---|
| **幫他打字 / 寫 code** | 他學不到，而且下午一定會再卡 | 坐旁邊看他打 |
| **說「這很簡單」** | 對他不簡單。這句話會讓他不敢再問 | 「這裡確實容易卡」 |
| **一次講三個問題** | 認知超載，一個都記不住 | 一次一個，解完再看下一個 |

## 三、常見卡點（依發生頻率排）

### 開場：`claude` 裝不起來（最高頻）
```
① 打 claude --version 看錯誤
② command not found → PATH 問題，重開終端機
③ 權限錯誤 → 不要用 sudo，看 docs/setup/01
④ 5 分鐘沒解決 → 改用參照專案跟跑，午休再修
```
**不要在這裡花超過 5 分鐘。** 環境問題午休處理，不要卡住整班。

### 開場：沒有訂閱
```
→ 直接帶到 docs/setup/02-free-routes.md
→ 這個要 15–40 分鐘，助教一對一
→ 課前預習信有講，沒做的人要有心理準備會落後
```

### BUILD 1：第 3 題答不出來（「怎麼判斷做對了」）
**這是設計上刻意的卡點，不要太快放過。**
```
追問：「如果有兩個版本，你會看什麼、數什麼、比什麼？」
還是卡 → 換問：「什麼情況你會說『這個做壞了』？」
        （從負面例子回推判準通常比較容易）
```

### BUILD 5：考卷只有主流程
```
「空輸入的時候呢？」「輸入超長的時候呢？」
→ 通常問兩句他就自己想到了
```

### BUILD 6–7：跳過 RED 直接寫實作
```
→ 讓他刪掉重來一次
→ 這個痛要親身經歷，講一百遍都沒用
→ 說法：「我知道很煩，但你等一下重構的時候會感謝這個測試」
```

### BUILD 6–7：`/next` 只跑一輪
```
「一個數字不叫曲線。再跑一輪，我們看它會不會動。」
```

### BUILD 6–7：分數卡住不動
```
三種可能，依序問：
① 「你覺得有變好嗎？」→ 覺得有但分數沒動 = 考卷抓不到重點
② 「問題真的在這個檔案嗎？」→ 邊界劃錯
③ 「最近兩輪的改動是不是越來越小？」→ 到天花板了，該換做法
```

### BUILD 8：hook 改了沒反應
```
① 重開 claude 了嗎？（hook 在啟動時載入）  ← 九成是這個
② echo '{...}' | bash 直接測，看有沒有輸出
③ bash -x 跑，看卡在哪一行
```

### BUILD 8：不知道要寫什麼 command
```
問：「你今天跟 AI 講過最多次的同一句話是什麼？」
→ 那就是他的 command
```

### BUILD 9：資安掃出一堆東西
```
「只看阻擋項那幾條，建議項回家再修。」
→ 學員很容易被清單嚇到而停擺
```

### BUILD 9：部署失敗
```
「沒關係，有維運卡就算過關。部署卡在帳號的很多。」
→ 明確告訴他這不算失敗，不然他會覺得整天白做
```

## 四、什麼時候該讓他「跟跑」

出現以下任一情況，**讓學員改用 `labs/reference-project/` 跟著跑**：

- 環境問題卡超過 10 分鐘
- 他的題目落在任務分流的「先別做」那一格，且 5 分鐘內轉不出來
- 進度落後兩站以上

**跟跑不是放棄。** 他一樣會學到循環三問、檢查點、六種資產——
只是用老師的題目而不是自己的。**這比讓他呆坐一整天好太多。**

說法：
> 我們先用這個現成的題目把流程跑一遍，你自己的題目今天晚上再套。
> 流程學會了，換題目只是換內容。

## 五、全班性卡關的處理

**同一個地方 3 個人以上卡住 = 教材問題，不是學員問題。**

處理：
1. **喊停全班**，統一講一次
2. 記下來：卡在**哪一步的第幾步**
3. 課後開 issue 回報 —— **這是最有價值的教材回饋**

---

## 六、情緒處理

有人開始說「我是不是太笨」「大家都做得比我快」時：

```
❌ 「不會啦你很好」        ← 空洞，沒有幫助
✅ 「你卡的這個地方今天有 4 個人卡住，是教材的問題。
    我們先跳過這步，用參照專案往下走，這步晚點回來補。」
```

**把問題歸因到教材，不是歸因到人。** 而且這通常是真的。
