# 講師手冊

課程只使用一份學生教材：[`../BUILD.md`](../BUILD.md)。不要另外發答案、投影片、積木或流程卡；每增加一個入口，學生就多一次迷路機會。

## 教學目標

課程結束時，學生必須能：

1. 說出 SmartTrip FX 哪些判斷交給 AI、哪些規則留在 code。
2. 把需求寫成可 pass/fail 的 acceptance criteria。
3. 依 ticket 完成一次真實 red → green → refactor。
4. 用命令輸出而不是感覺證明完成。
5. 知道下一個專案應先用 `/workflow`，而不是盲走完整流程。

這五項是驗收，不要求背 Skill 名稱。

## 建議課表

| 段落 | 時間 | 學生動作 | 講師只檢查 |
|---|---:|---|---|
| 第 0–1 章 | 25 分 | 開機、建立 project contract | 環境與真相源讀對 |
| 第 2 章 | 30 分 | 固定需求與 AI/code 邊界 | 沒有模糊規則 |
| 第 3–4 章 | 30 分 | 產 spec、切三張票 | criteria 可 pass/fail |
| 休息 | 10 分 | | |
| 第 5 章 | 90–150 分 | 三個 TDD vertical slices | 有 RED 證據、一次一票 |
| 第 6 章 | 30 分 | review、full test、commit | 沒把未跑寫成通過 |
| 第 7 章 | 15 分 | 回顧與遷移 | 能說出下一個專案第一句 |

完整課約 4–5 小時。90 分鐘示範版只跑第 0、2、3 章，再由講師示範第 5.1 與第 6 章；不要用額外題目填時間。

## 課前準備

學生只需要：Git、Python 3.11+、Claude Code、macOS/Linux/WSL。核心課程不需要 API key、MCP、Node、Docker 或雲端帳號。

講師應在乾淨 clone 親自走完 [`BUILD.md`](../BUILD.md)，確認：

```bash
python3 --version
claude --version
git status --short
```

不要在課前發預建專案。需要展示時，現場照同一份 prompt 產生；學生看到生成與驗證過程，才學得到方法。

## 巡場順序

學生卡住時只做四件事：

1. 指出他目前在哪一章、缺哪個通過條件。
2. 請他貼該章的「卡住就貼」。
3. 看最窄命令的真實輸出，不代替他寫 code。
4. 同一路徑失敗三次就回到 spec 或最初假設，不做第四次微調。

同一處有三位學生卡住，視為教材缺陷。記錄章節、原 prompt、實際輸出與失敗命令，課後修改教材，不把問題歸因給學生。

## 各章唯一檢查點

| 章 | 問學生一句話 |
|---|---|
| 0 | 哪些是建議，哪些由 hook 強制？ |
| 1 | 後續 Skill 從哪裡讀測試命令？ |
| 2 | 為什麼 unknown 要計入現金？ |
| 3 | 哪一條 criterion 最容易直接寫成 test？ |
| 4 | 為什麼 CLI ticket 被前兩張阻擋？ |
| 5 | 你能指出哪一次 RED 嗎？ |
| 6 | 哪個完成宣稱有命令輸出支持？ |
| 7 | 下一個專案的第一句是什麼？ |

## 沒網路或額度不足

核心產品不連網，但 Claude Code 本身仍需可用。若課中無法呼叫模型：

- 兩人一組，輪流貼 prompt 與讀通過條件。
- 全班共看講師 terminal，學生先在紙上判斷下一個輸出與測試。
- 不提供預建 `labs/`；恢復連線後從該章重新產生，避免答案與實際 Skill 漂移。

環境問題超過 10 分鐘就改成配對，不讓全班停在安裝階段。

## 教材 UX 規則

修改 [`BUILD.md`](../BUILD.md) 時，必須同時滿足：

- 學生入口仍只有一個。
- 每個操作區塊只要求一個動作。
- 每個 Skill 名稱都能在 `.claude/skills/` 找到。
- 每章都有預期輸出、通過命令與修正句。
- 範例答案直接放在使用它的章節，不建立 `labs/`。

最後驗證所有相對連結與 fenced commands，再用乾淨 clone 完整走一次。
