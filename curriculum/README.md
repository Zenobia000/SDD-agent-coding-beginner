# 講師手冊：Progressive SDD

> 這一份是 **CookCard 教材**（`BUILD.md` 七站）的帶課指南。
> 另有 [`sunny-sprint.md`](./sunny-sprint.md) —— 用這套方法論開的兩週 RAG 營，
> 題目與形式都不同，公開的是課表與 Rubric。兩份不要混用。

> 給講師。學生不需要讀這一份。
>
> 這門課和另外兩條線的教法**完全不同**。照著 `claude` / `antigravity` 那套帶會失敗。

**這一份管節奏與教法**：三段式時程、開課前必做、常見帶課失誤。
**逐站的現場對照在 [`TEACHING.md`](./TEACHING.md)**：每一站學生會打什麼、卡在哪、你該說什麼、什麼時候准他翻 [`COOKBOOK.md`](./COOKBOOK.md)。兩份都要看過。

---

## 最重要的一件事

**這門課的價值全部在「學生自己做決定」的那些時刻。**

你會很想在學生卡住時直接給答案 —— 尤其是選型那幾關。**不要給。**

給了答案，這門課就退化成另一本照貼照跑的書，而那已經有兩條線在做了。

正確的介入方式是**把問題縮小**，不是給答案：

| 學生說 | 不要回 | 要回 |
|---|---|---|
| 「要用 VLM 還是 STT？」 | 「用 VLM」 | 「你 baseline 跑出來幾樣食材？caption-only 那支呢？」 |
| 「schema 該怎麼設計？」 | 給一份 schema | 「『適量』你打算怎麼存？先回答這一題」 |
| 「這樣算做完了嗎？」 | 「算」 | 「你的通過訊號跑起來是什麼？」 |

第三題是這門課最常出現的，也是最關鍵的。**永遠把「算不算做完」丟回給學生自己定義的驗收訊號。**

---

## 節奏

這門課**不是一次上完**。建議切成三段，中間讓學生自己做。

| 段 | 內容 | 時間 | 形式 |
|---|---|---|---|
| **第一段** | 心法篇 + 第 0–1 站 | 3 小時 | 講師帶 |
| 自主 | 第 1 站收尾、第 2–3 站 | 一到兩週 | 學生自己做，非同步問答 |
| **第二段** | 第 2–3 站檢討 + 第 4 站 | 3 小時 | 講師帶，重點在 review |
| 自主 | 第 5 站（一張票一個 session） | 一到兩週 | 學生自己做 |
| **第三段** | 第 6–8 站 + 收尾 | 3 小時 | 互相跑對方的 Runbook |

**中間的自主期不能省。** 不變量 4（可逆性）與 Signal 3（反覆 regression）需要時間才會顯現 —— 同一個檔案「兩週內壞過兩次」在三小時的工作坊裡不可能發生。壓縮成一天的話，學生只會學到形式。

---

## 第一段（3 小時）

| 時間 | 內容 | 巡場重點 |
|---|---|---|
| 0:00–0:40 | 心法篇。**帶讀，不是自己看** | 七條不變量每條問一次「你遇過嗎」 |
| 0:40–1:10 | 第 0–1 站：`/setup-skills` → `/grilling` | 看 `Non-goal` 是不是空的 |
| 1:10–1:20 | 收：三個人念自己的 `Success` | 挑一個不可驗證的出來公開改 |
| 1:20–2:30 | 第 1 站：`/grilling` 實際被問倒一次 | 看有沒有人在建專案結構而不是跑起來 |
| 2:30–2:50 | **全班一起跑 `caption-only`** | 這是整堂課的高峰，不要跳過 |
| 2:50–3:00 | 交代自主期任務 | 明講：不要寫測試 |

### 2:30 那一刻怎麼帶

讓所有人同時跑 `caption-only`。選純 STT 的人會發現份量是空的。

**不要解釋為什麼。** 問：「份量在哪裡？」讓他們自己去看影片畫面。

看到字卡的那一秒，多模態的必要性就不用教了。

---

## 第二段（3 小時）：重點是 review，不是進度

| 時間 | 內容 |
|---|---|
| 0:00–0:40 | 兩兩交換 spec，互相找「不可驗證的 Acceptance Criteria」 |
| 0:40–1:00 | 收：公開改一份寫得最模糊的 |
| 1:00–1:30 | 第 3 站的刻意坑：把 spec 交給 AI 實作，找出它替你決定了什麼 |
| 1:30–2:40 | 第 4 站：`/to-tickets` 拆曳光彈票 |
| 2:40–3:00 | **跑 `multi-dish`**，讓 schema 當場崩掉 |

### 2:40 那一刻怎麼帶

`multi-dish` 會打破「一支影片 = 一張食譜卡」的假設，而學生已經存了幾十筆資料。

**這時全班一起寫 ADR。** 這是整門課唯一適合「一起寫」的產出 —— 因為三個選項（遷移 / 不做 / 折衷）都合理，公開比較取捨的價值最大。

---

## 第三段（3 小時）：互相當閘門

| 時間 | 內容 |
|---|---|
| 0:00–1:30 | 第 7 站：`/wizard`、排程、Runbook |
| 1:30–2:00 | prompt injection 那個坑，全班一起試 |
| 2:00–2:45 | **交換機器**，照對方的 Runbook 跑起來 |
| 2:45–3:00 | 收尾五題 |

2:00 那一段是全課的驗收。學生卡住的每一個地方，都是對方 Runbook 缺的一行 —— 而且他們會親身體會不變量 7：**你自己不能當那個閘門。**

## 開課前必做

| 項目 | 說明 |
|---|---|
| **確認 fork 即用** | 拿一台乾淨機器 fork、clone、`claude`、打 `/compass`，確認技能載得到 |
| **看過六支 fixture 影片** | 已挑好在 [`docs/FIXTURES.md`](../docs/FIXTURES.md)。你要確認的是 `caption-only` 那支的份量真的在畫面字卡上 —— 那一點沒辦法自動驗 |
| **寫好 `expected.json`** | 每支的必要食材、最少數量、已知模糊項、不得出現的幻覺項 |
| **預先下載** | audio / captions / frames 進版控，教室網路撐不住三十個人同時抓 |
| **自己跑一遍第 1 站到第 5 站** | 至少確認 baseline 那支真的抽得出東西，且技能在 fork 裡叫得動 |
| **確認模型額度** | 學生會反覆重跑，長影片特別燒 |

**沒有 fixture 就不要開課。** `BUILD.md` 的通過訊號全部建立在它上面，沒有它整門課就退回成「憑感覺說做完了」。

## 常見的帶課失誤

| 失誤 | 後果 |
|---|---|
| 給了選型答案 | 學生學不到判斷，課退化成照貼照跑 |
| 壓縮成一天 | 第 3 站到第 7 站的訊號來不及顯現，只學到形式 |
| 跳過 `caption-only` | 多模態變成規定而不是需求，選型那一關就空了 |
| 幫學生定義「做完」 | 直接毀掉不變量 1 |
| 準備了參考實作 | 一旦有人看到，全班都會照抄 |
| 太早放行 `COOKBOOK.md` | 學生學到打字，學不到判斷。放行門檻見 [`TEACHING.md`](./TEACHING.md) |

最後兩條特別注意。

**這門課刻意沒有參考實作**，理由寫在 `BUILD.md` 附錄。你自己跑過的版本請不要外流給學生。

`COOKBOOK.md` 是公開的，你擋不住 —— 所以帶課的關鍵不是禁止，是**讓學生在翻之前先痛過一次**。每一站的放行門檻寫在 [`TEACHING.md`](./TEACHING.md)，**開課第一天就要把四個高風險節點的門檻講明白**，比事後禁止有效。

## 學生會問而你該怎麼回

**「我這樣做對不對？」**
→ 「你的通過訊號跑起來是什麼？」

**「老師你會怎麼做？」**
→ 「我會先問這個決定錯了要多少成本改回來。你算過嗎？」

**「AI 說這樣就可以了。」**
→ 「它跑過了嗎？輸出貼給我看。」

**「這個 schema 是不是最佳解？」**
→ 「沒有最佳解。你寫下取捨了嗎？」

四個回答的共同點：**把判斷丟回去，但給他一個具體的下一步。** 不是丟著不管。
