# TDD 強制模式 —— 追加規則

> 範本：**接在 `AGENTS.safe.md` 後面**，貼進同一份 `AGENTS.md`。
> 文字規則 AI 大部分時候會遵守，但不是每一次。要真的擋住，搭配 [`../hooks/`](../hooks/) 的 hook。

## 開發順序（每一個行為改變都照這個順序）

1. **先寫測試。** 測試名稱要引用規格編號，例：`test_ac_02_1_annual_leave_insufficient`。
2. **跑測試，貼出失敗的輸出。** 測試一開始就通過，代表它沒有在測東西，要重寫。
3. **等我確認紅燈之後**，才能修改業務邏輯。
4. 寫最少的程式碼讓測試通過。跑**完整**的測試，貼出結果。
5. 全綠之後才能重構。重構過程中測試必須一直是綠的。

## 測試的規矩

- 不准刪除、跳過（skip）或放寬既有的測試來讓它通過。
- 測試失敗時，修的是實作，不是測試。如果你認為測試本身錯了，**停下來說明理由**，由我決定。
- 單元測試不准呼叫真的 LLM 或外部 API，一律用假物件（fake）。
- 每一條驗收條件（`AC-xx-x`）都要有對應的測試。

## 修 bug 的順序

1. 先寫一個能重現這個 bug 的測試，跑給我看它失敗。
2. 再修實作。
3. 跑完整測試，確認沒有改壞別的地方。

## 說「完成」之前

- [ ] 完整測試全綠，輸出已貼出
- [ ] `git diff` 裡沒有修改到測試的斷言（assert）
- [ ] 每個新行為都有測試
