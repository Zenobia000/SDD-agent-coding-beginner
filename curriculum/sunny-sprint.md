# Sunny Sprint：AI 協作交付能力培育營

> 兩週制。用這個 repo 的方法論，做出一個**可被公開展示、附量化指標**的 AI 應用專案。
>
> 這是課程大綱與評分標準的公開版。定價與報名資訊另行公告。

---

## 這門課賣什麼

不是「AI 工具速成」，是**可驗收的交付成果**。

差別在收尾：工具速成課結束時你會用工具了；這門課結束時你手上有一個**別人能打開、能評分、能寫進履歷**的東西。

### 我們承諾

> **兩週內交付一個可公開展示並附量化指標的 AI 應用專案。**

交付物會通過 Rubric 七維度評分、拿到教練回饋、留下作品證據。

### 我們不承諾

薪資漲幅、轉職保證、就業率。

**這一段是刻意寫的。** 任何承諾這三件事的課都在賣你控制不了的東西 —— 它們取決於市場、你的既有背景與運氣，不取決於這兩週。

## 適合誰

| | |
|---|---|
| **主要對象** | 3–5 年經驗的工程師與產品經理 |
| **動機** | 想用 AI 提升能力，不是被 AI 取代 |
| **典型痛點** | **會用工具，但無法獨立交付一個可驗收的完整作品** |

### 入學條件

- 基本程式能力（Python 或 JavaScript）
- Git 版本控制基礎
- **能承諾每日 3–4 小時** —— 兩週制沒有補課空間，這條是硬的

報名後有 30 分鐘線上診斷：RAG 概念題、程式碼閱讀與問題解析。目的不是刷人，是讓你在付費前知道自己會不會跟不上。

## 形式

| | |
|---|---|
| 週期 | 2 週（14 天） |
| 規模 | 每期 16–24 人，分 4 小隊，每隊 4–6 人 |
| 節奏 | 每日站會 + 每週 Demo Day + 最終驗收 |
| 支援 | Discord 專屬社群、每日 office hour 2 小時、卡關 24 小時內回應 |

## 題目：RAG 問答系統

選 RAG 的理由不是它熱門，是它**可驗收指標明確** —— 準確率、回應時間都能量化，不用靠「感覺不錯」來判斷做完沒。

技術複雜度也剛好：不會簡單到兩天做完，也不會難到兩週做不出來。

**交付物定義**：一個可部署的 RAG 問答系統，含知識庫管理、問答介面、評估指標，並通過 Rubric 七維度評分。

## Rubric：七維度 100 分

**評分標準開課前就公開，不是事後才知道。** 你從第一天就該知道自己在被什麼標準衡量。

| # | 維度 | 分 |
|---|---|---|
| 1 | 問題定義與需求分析 | 15 |
| 2 | 技術方案選型 | 15 |
| 3 | 可重現性與可部署性 | 15 |
| 4 | 程式品質與測試 | 15 |
| 5 | 功能完整性 | 15 |
| 6 | 效能與可擴展性 | 10 |
| 7 | 交付完整度與展示 | 15 |

### 各維度的分級描述

<details>
<summary>展開完整評分標準</summary>

**1. 問題定義與需求分析（15）**
- 優秀 13–15：清晰定義商業問題，完整 PRD，有明確成功指標
- 良好 10–12：基本問題定義，PRD 完整度 80%，指標模糊但存在
- 及格 7–9：問題定義含糊，PRD 缺失重要部分，無具體指標
- 不及格 0–6：無法清楚說明要解決什麼問題

**2. 技術方案選型（15）**
- 優秀 13–15：技術選擇有理有據，考慮成本效益，有替代方案
- 良好 10–12：技術選擇合理，有基本考量但不夠全面
- 及格 7–9：技術選擇可行但缺乏深度思考
- 不及格 0–6：技術選擇不當或無法說明原因

**3. 可重現性與可部署性（15）**
- 優秀 13–15：一鍵部署，完整環境設定，有 Docker 支援
- 良好 10–12：基本可部署，需要少量手動設定
- 及格 7–9：可運行但需要複雜設定，文檔不完整
- 不及格 0–6：**無法在乾淨環境中運行**

**4. 程式品質與測試（15）**
- 優秀 13–15：有單元測試與整合測試，結構清晰，有錯誤處理
- 良好 10–12：有基本測試，程式碼品質良好
- 及格 7–9：可運行但缺乏測試與錯誤處理
- 不及格 0–6：品質差，容易崩潰

**5. 功能完整性（15）**
- 優秀 13–15：所有核心功能完整，有額外亮點
- 良好 10–12：核心功能完整，基本需求滿足
- 及格 7–9：主要功能可用但有明顯缺失
- 不及格 0–6：核心功能不完整或無法使用

**6. 效能與可擴展性（10）**
- 優秀 9–10：有效能監控，考慮擴展性，有優化措施
- 良好 7–8：效能可接受，有基本監控
- 及格 5–6：可運行但效能一般
- 不及格 0–4：效能問題明顯影響使用

**7. 交付完整度與展示（15）**
- 優秀 13–15：完整文檔、清晰展示、有使用說明，pitch 專業
- 良好 10–12：文檔基本完整，展示清楚
- 及格 7–9：有基本文檔與展示但不夠專業
- 不及格 0–6：交付物不完整，無法有效展示

### 通過標準

| | |
|---|---|
| **通過線** | 70 分 |
| **優秀作品** | 85 分以上 |
| **評分方式** | **雙盲評分** —— 兩位教練獨立打分，差異超過 10 分啟動仲裁 |

雙盲不是形式。單一評分者會被「這個學生很努力」影響，而 Rubric 衡量的是交付物不是努力程度。

## 這門課和 repo 教材的關係

| | 這個 repo | Sunny Sprint |
|---|---|---|
| 形式 | 自學教材，免費 | 有教練、有同儕、有評分的兩週營 |
| 題目 | SmartTrip FX（工具線）、CookCard（工程線） | RAG 問答系統 |
| 驗收 | 自己驗 | **雙盲 Rubric 評分 + 教練回饋** |

repo 的教材可以獨立走完。Sunny Sprint 加的是**外部驗收壓力** —— 也就是[心法篇](../PRINCIPLES.md)不變量 7 說的那件事：**你自己不能當那個閘門。**

## 教練配置

- 主教練 1 名：課程設計與最終評分
- 助教 2–3 名：日常答疑與進度追蹤
- 客座專家 1–2 名：技術分享與業界經驗

所有教練統一培訓，開課前跑一次評分標準校準會議 —— 否則七維度會變成七個人各自的主觀感受。
