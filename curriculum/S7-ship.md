## 課堂 15 分鐘版

**老師講**（5 分）：

1. `/ship` 的順序是**由便宜到昂貴、由可逆到不可逆**。先做幾秒鐘的檢查，最後才做不可逆的部署
2. `git rm .env` 之後 key **仍然在歷史裡**。公開 repo 等同外洩——**唯一正確的處理是輪換那把 key**
3. 維運卡最重要的一格是「**不可回滾的操作**」

**學生做**（20 分）：打 `/ship`，跟著它走。紅燈就停下來修。

老師此時要提醒：**沒部署成功不算失敗。** 有資安報告和維運卡就算過關——
部署卡在帳號/網路的人很多，不要為了上線而犧牲前面的紀律。

## 動手

1. 跑總檢
   ```
   > /ship
   ```
   它會依序跑：`/verify` → `/sec-scan` → 考卷回測 → `/ops-card` → 部署。

2. 紅燈就停下來修，**不要跳站**

3. 特別確認資安這兩件事
   ```bash
   # .env 有沒有曾經被提交過
   git log --all --oneline --name-only --diff-filter=A -- '*.env' '*.env.*'

   # 歷史裡有沒有 key
   git log -p --all -S 'sk-' --oneline | head
   ```
   **有的話：立刻輪換那把 key**，不是刪檔案就好。

4. 檢查 `docs/OPS.md` 的第 6 格（怎麼回滾）**有沒有實際演練過**

5. 部署（可選）
   ```bash
   # 照 docs/OPS.md 第 3 格的指令
   ```

6. 收工
   ```
   > /retro
   ```

## 回家展開版

### 為什麼 `/ship` 的順序不能調換

```
/verify      幾秒鐘      可逆
/sec-scan    幾十秒      可逆
考卷回測      幾分鐘      可逆
/ops-card    十幾分鐘    可逆
部署         幾分鐘     ← 可能不可逆
```

**先做便宜的、可逆的。** 部署到一半才發現 lint 沒過，代價高太多。

### 資安：三層防線

| 層 | 誰 | 何時 | 擋什麼 |
|---|---|---|---|
| ① | `block-secret-write.sh` hook | 寫檔當下 | 明顯的憑證寫入 |
| ② | `.githooks/pre-commit` | commit 時 | 漏網的憑證、誤加的 `.env` |
| ③ | `/sec-scan` | 交付前 | **歷史**、暴露面、邏輯漏洞、依賴 |

前兩層是機械的、便宜的。第三層是**需要判斷**的那一層。

### git 歷史裡的 key 為什麼特別危險

```
Day 1：不小心 commit 了 .env
Day 2：發現了，git rm .env && commit
Day 3：你以為安全了
    ↓
實際上：git log -p 一撈就有。push 到公開 repo = 已外洩
```

**正確處理順序**：
1. **立刻輪換那把 key**（最重要，且不可延後）
2. 確認是否已 push（push 過就假設已外洩）
3. 清歷史（`git filter-repo` / BFG）—— 這是善後，不是修補

### 最常漏的資安問題：IDOR

**換個 id 就能看別人的資料。**

```
GET /api/orders/1001   → 你的訂單 ✓
GET /api/orders/1002   → 別人的訂單 ← 有檢查嗎？
```

UI 上藏起來不算數。**每個資源存取都要在後端檢查歸屬。**

### 維運卡：失敗模式的排序

**依實際發生過的頻率排，不是依理論可能性。** 第一次寫時用這個預設：

```
1. 環境變數 / 設定沒帶到    ← 最常見，且最容易誤診
2. 依賴的外部服務掛了或改了
3. 資料格式跟預期不一樣
4. 資源不足
5. 程式本身的 bug           ← 其實最少見
```

每次真的壞掉後回來更新這個順序——**這是維運卡唯一會持續增值的部分。**

### 沒演練過的回滾等於沒有回滾

```
❌ 「回滾：revert 上一個 commit 然後重新部署」
✅ 「回滾：<指令>
    上次演練：2026-07-30，耗時 2 分 10 秒
    會失去：這段期間的寫入（約 N 筆，可從 log 重放）」
```

**沒演練就在維運卡上標「未演練」**，不要寫得像已驗證。

### 健康檢查要兩層

```
淺層：/healthz 回 200          ← 只證明程序活著
深層：跑一次真實的端到端動作     ← 證明使用者真的能用
```

只有淺層的系統會出現「監控全綠但沒人能用」。

### 從可控系統到產品（想繼續往下走的人）

技術做完了，剩下的是商業判斷：

| 階段 | 要先答對的問題 | 產出 |
|---|---|---|
| Idea | 這個痛點是真的嗎？ | 可驗證假設 |
| MVP | 做什麼、**不做什麼**？ | Scope Doc |
| Launch | 怎麼穩定運轉？ | **你今天做的維運卡** |
| Scale | 為什麼別人離不開我？ | 護城河 |

**你今天已經完成前三階段的骨架了。**

### 授權矩陣：哪些能放手

```
低風險 ──── 自動執行 ────→ 事後查 log
              │
           風險線 ← 你要畫的就是這條
              │
高風險 ──── 人類核准 ────→ 授權層級必須可驗證
```

| 動作 | 可逆？ | 風險 | 授權方式 |
|---|---|---|---|
| 部署新版程式 | ✅ | 低 | 自動 |
| 加欄位的 migration | ✅ | 低 | 自動 |
| 刪欄位 / 刪資料 | ❌ | 高 | **人類核准** |
| 金流相關 | ❌ | 高 | **人類核准** |

**全自動是陷阱，全人工是白做。** 你的工作是畫出那條風險線。
