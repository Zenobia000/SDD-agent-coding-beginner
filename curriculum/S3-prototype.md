## 動手

1. 打開一個一站式平台（三選一）

   | 平台 | 適合 | 帳號 |
   |---|---|---|
   | Google AI Studio | 有 LLM 呼叫的工具 | Google 帳號 |
   | Replit | 要有前端介面的 | 免費方案 |
   | v0 / Bolt 類 | 純前端畫面 | 免費額度 |

2. 貼上你的 spec，加這一句在最後
   ```
   請依上面的規格產出一個可以直接執行的最小版本。
   要求：
   - 單一檔案優先，能跑起來最重要
   - 不要加規格裡沒有的功能
   - 需要 API key 的地方留成環境變數，不要寫死
   ```

3. 跑起來，**實際操作一次**

4. 拿 S2 的考卷，**手動跑三筆**（不用全部 10 筆，時間不夠）
   ```
   v0 通過率（手動抽 3 筆）：___ / 3
   ```

5. 把 v0 的產出物存進專案，**不要拿它繼續開發**
   ```bash
   mkdir -p prototype && # 把平台的產出存進 prototype/
   ```

## 回家展開版

### 一站式平台的定位：它不是 prompt 工廠

很多人把 AI Studio 當「寫 prompt 的地方」。**那是誤用。**

它真正的價值是：
```
你有規格 → 丟進去 → 30 分鐘拿到會動的東西 → 驗證方向對不對
```

**驗證方向，不是產出成品。** 拿它的輸出繼續開發，會遇到：
- 沒有版控
- 沒有測試
- 架構是它猜的，不是你設計的
- 換個需求就要整份重來

所以 S4 是**重新開始**，不是接著 v0 改。

### 為什麼 v0 要丟掉

這叫「**用完即丟的原型**」（throwaway prototype），是刻意的：

| | 原型 v0 | 正式版 v1 |
|---|---|---|
| 目的 | 驗證方向 | 交付 |
| 品質 | 能動就好 | 有測試、有文件 |
| 壽命 | 今天下午 | 六個月後還維護得動 |
| 誰寫的 | 平台猜的 | 你設計的 |

**捨不得丟 v0 是最常見的陷阱。** 那份 code 沒有測試保護，你不敢改，最後被它綁住。

### 三個平台的取捨

| | AI Studio | Replit | v0 / Bolt |
|---|---|---|---|
| 強項 | LLM 呼叫、prompt 迭代 | 完整環境、能跑後端 | 前端畫面漂亮 |
| 弱項 | 沒有真的執行環境 | 免費方案有資源限制 | 只有前端 |
| 適合的題目 | 摘要 / 分類 / 抽取 | 有 API + DB 的 | 儀表板 / 表單 |

### 沒有網路 / 平台掛掉怎麼辦

用 `claude` 本機直接跑：
```
> 依 docs/PRD.md 產一個單檔的最小可執行版本，放在 prototype/
```

會慢一點但一樣達到目的。老師的應急方案見
[`instructor/fallback.md`](./instructor/fallback.md)。

### 這一站真正在教什麼

**架構設計先於工具選擇。**

你已經有 spec 和考卷了，所以：
- 換任何平台都能重跑
- 平台掛了不影響你的判斷
- 產出好不好，你有客觀依據可以判斷

**沒有 S1、S2 就直接玩平台的人，只能說「感覺還不錯」。**
