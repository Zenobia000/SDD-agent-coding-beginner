# S1 問對問題

## 結論卡

| | |
|---|---|
| **做什麼** | 把一句「好煩」變成一個**可判斷對錯**的題目 |
| **為什麼** | 這是四拍的第①拍——邊界劃不出來，後面全部白做 |
| **產出** | `decision-card.md`（現況數字 + 可判斷的成功條件 + 不做什麼） |
| **下一步** | 跑 `/gate` 確認 S1 過關 |

**這一站對「題目」跑一輪四拍。**

---

## 課堂 15 分鐘版

**老師講**（5 分）：

1. 以前教「怎麼寫 prompt」。現在最貴的能力是**問對問題**——因為寫 code 變便宜了，**決定做什麼變昂貴**
2. 判斷一件事該不該交給 AI，只看一個問題：**你寫得出 `check()` 嗎？**
3. 決策卡最重要的欄位是「**不做什麼**」——那是你對抗範圍膨脹的主防線

**學生做**（10 分）：在 `claude` 裡打 `/frame`，它會**一次問一題**，共五題。

老師巡場時只盯一件事：**第 3 題（怎麼判斷做對了）有沒有被含糊帶過。**

## 動手

1. 用一句話寫下你的痛點（不要超過 20 字）
   ```
   > /frame 每天手動整理三個網站的匯率很煩
   ```

2. 回答五題。**一次一題，不要跳著答**

3. 卡在第 3 題（「怎麼判斷做對了」）時，用這個方式逼自己：
   > 如果有兩個版本擺在我面前，我會**看什麼、數什麼、比什麼**來決定哪個好？

4. 檢查產出的 `decision-card.md`，確認「不做什麼」欄位**至少有兩條**

5. 更新進度
   ```bash
   echo "S2 beat1" > .claude/.station
   ```

## 回家展開版

### 任務分流表：這件事到底該不該丟給 AI

| 能用程式驗證？ | 做錯的代價 | 結論 |
|---|---|---|
| 可以 ✓ | 低 | **直接交給 AI 全自動**，事後看 log |
| 可以 ✓ | 高 | **AI 做，人核准**——動作可逆才自動 |
| 部分可以 | 任意 | **人機協作**：AI 產候選，人挑 |
| 不行 ✗ | 任意 | **先別做**——想辦法讓它變成可驗證的 |

**一句話判斷：寫不出 `check()` 的任務，先別丟給模型。**

落在最後一格不代表這題不能做，代表**你還沒把它拆到可驗證**。例如：

```
「幫我寫出好文案」        → 寫不出 check() ❌
    ↓ 拆
「文案 ≤ 30 字」          → 可驗證 ✓
「包含產品名與一個動詞」   → 可驗證 ✓
「不出現這 10 個禁用詞」   → 可驗證 ✓
    ↓
變成「AI 產 20 個候選，程式篩掉不合格的，人從剩下的挑」→ 人機協作
```

### 為什麼「不做什麼」是主防線

因為做功能變太便宜了，需求會無限蔓延。

```
成本趨近零 → 「順便加一個 ___ 好了」→ 範圍膨脹 → 什麼都沒做完
```

`decision-card.md` 的「不做什麼」欄位是你**事先寫給未來的自己**的約束。
AI 也會讀它——`CLAUDE.md` 有一條「不做超出 spec 範圍的事」。

### 商業判斷：這題值不值得做

三個數字算出來就有答案：

```
一年成本 = 一次花的時間 × 頻率 × 12
```

例：每天 15 分鐘 × 250 個工作日 = **62.5 小時／年**。
如果做這個工具要花 8 小時，第 6 週就回本。

**算不出這個數字，通常表示這件事沒有你以為的那麼煩。**

### 護城河：為什麼別人換不掉你

（這段對想把作品變產品的人才重要，做作品集可以先跳過）

| 護城河 | 為什麼難複製 |
|---|---|
| **深度** | 砸錢買不到的領域理解 |
| **專有資料** | 別人補不齊 |
| **工作流綁定** | 切換成本太高 |

**技術本身不是護城河**——人人都能用 AI 拼出同樣的東西。

### 為什麼不先教寫 prompt

因為模型變強之後，prompt 技巧在快速貶值：

```
昨天要手寫的技巧（一步一步想、先思考再行動）
    ↓
今天變成內建參數
```

而**「要做什麼」和「怎麼驗證」這兩件事，模型再強也不會幫你決定**。
這就是把 S1 排在最前面的理由。
