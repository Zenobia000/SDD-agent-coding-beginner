# 規格驅動與 AI 自動化開發實戰營（4 天）

> 捨棄厚重的 Word 文件，以 Claude Code / Codex 為核心，透過「文件降維」與「垂直切片」，
> 走完從商業需求到測試驗收的完整軟體生命週期。

---

## 適合誰

**不限職位。** 在企業裡走過流程，或者看得懂一張流程圖的人，都跟得上。

| 你是 | 你會帶走什麼 |
|---|---|
| **主管** | 判斷團隊導入 AI 開發的成熟度，知道哪些環節不能交給 AI |
| **PM / SA** | 寫出 AI 讀得懂、人驗得了的規格；不寫程式也能審查 AI 的產出 |
| **QA** | 把驗收條件展開成測試矩陣，讓 AI 窮舉邊界、由你判斷哪些有意義 |
| **初學工程師** | 用 agent 把規格做成有測試保護的程式，而不是一次生成一大坨再祈禱 |

**課前要會的**：用過任何一種 AI 聊天工具；能照著說明在終端機打指令。
**不用會的**：寫程式。工程軌的人會寫一點 Python 會更順，但不是必要。

---

## 核心觀念：人收斂，AI 發散

| AI 負責 | 人負責 |
|---|---|
| 生成草稿、窮舉情境、寫程式、跑測試 | 決定要做什麼、不做什麼、什麼叫做完 |
| 速度 | 方向 |
| 給你十個選項 | 選一個，並為它負責 |

4 天的每一個單元都在練這件事。

## 分組方式

每組 3–4 人，**角色混搭**：至少一位寫規格的（PM / SA / 主管）、一位寫程式的（工程師）。

| 軌 | 主要負責 | 每個單元都會有 |
|---|---|---|
| 📋 **規格軌** | 需求、驗收條件、審查 AI 產出 | 「規格軌做什麼」 |
| 🛠️ **工程軌** | 讓 agent 實作、跑測試、修 bug | 「工程軌做什麼」 |

兩軌在同一個 repo 裡工作。規格軌寫的文件，就是工程軌餵給 agent 的輸入 —— 寫得不清楚，工程軌當場就會卡住，這是故意的。

## 每天的固定格式

每一份 `DAYn.md` 的每個單元都有這幾段：

| 段落 | 是什麼 |
|---|---|
| **為什麼** | 這個單元要解決的問題，一兩句 |
| **重點** | 講師會講的觀念 |
| **實作** | 規格軌、工程軌各做什麼 |
| **可以這樣問 AI** | 參考提示詞。先自己改成你的版本再用，原封不動貼上的效果通常最差 |
| **通過訊號** | 你自己能檢查的東西，做到了才算完成這個單元 |
| **常見卡關** | 前幾屆最常卡住的地方 |
