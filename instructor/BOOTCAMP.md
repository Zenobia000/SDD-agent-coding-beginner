# 講師手冊：4 天實戰營

> 給講師。學員教材在 [`1-bootcamp/`](../1-bootcamp/)。這一份管的是**節奏、高峰時刻與帶課失誤**。

---

## 最重要的一件事

**這門課的價值在「人做決定」的那些時刻。** 教材給了提示詞、給了模板，但每個單元都有一個決定只能由學員做：要不要做、做到哪、怎樣算過。

學員卡住時，**縮小問題，不要直接給答案**：

| 學員說 | 不要回 | 要回 |
|---|---|---|
| 「這樣算做完了嗎？」 | 「算」 | 「你的通過訊號跑起來是什麼？」 |
| 「AI 說可以了」 | 「好」 | 「它跑過了嗎？輸出貼給我看」 |
| 「颱風假要怎麼算？」 | 給一個規則 | 「你們公司怎麼算？不知道的話，寫進待決事項」 |
| 「準確率 80% 夠嗎？」 | 「夠」或「不夠」 | 「錯的 20% 會發生什麼事？有退路嗎？」 |

## 開課前必做

| 時間 | 項目 |
|---|---|
| 開課前 2 週 | 寄出 [`0-setup/`](../0-setup/) 檢核表，要求學員回報第 4 步的結果 |
| 開課前 1 週 | 追蹤沒回報的人。**環境沒好的人，第一天上午會拖住整組** |
| 開課前 1 週 | 自己用乾淨的機器，Claude Code 與 Codex **各**走一次 Day 1 單元 2 |
| 開課前 3 天 | 確認 `4-starter/` 能跑、`pytest` 全綠、假 LLM 能用 |
| 開課前 3 天 | 準備 eval 起始集：至少 30 句，正確答案人工確認過 |
| 開課前 1 天 | 依報名資料分組，**確保每組至少有一位規格軌、一位工程軌** |
| 開課當天 | 準備備用 API key 或備用帳號，以防有人的額度用完 |

## 每天的高峰時刻

每一天都有一段**不能省、不能趕**的時刻。其他單元可以壓縮，這幾段不行。

| 天 | 時刻 | 為什麼不能省 | 怎麼帶 |
|---|---|---|---|
| Day 1 | 單元 4：兩組交換圈模糊句子 | 學員第一次發現「我覺得很清楚」和「別人看得懂」是兩回事 | 挑一條全班都覺得清楚、但其實有兩種解讀的，公開改 |
| Day 2 | 單元 5：「交給誰」那張表 | 整個系統的安全與正確性，都建立在這張表上 | 一定會有組想把「算剩餘天數」交給 AI。讓他們說理由，再問：「算錯一次會發生什麼？」 |
| Day 3 | 單元 11：破壞測試 | 學員第一次看見測試的價值，而不只是聽說 | 有組的測試沒抓到時，**公開表揚**。那是最有價值的發現 |
| Day 4 | 單元 14：prompt injection 現場 | 「叫 AI 不要聽」行不通，這件事要親眼看到 | 先讓大家試著用 prompt 擋，失敗之後再回到 Day 2 那張表 |

## 分組與兩軌

- 每組 3–4 人，至少一位規格軌、一位工程軌。
- **規格軌的人要親手跑驗收指令。** 不寫程式不代表不能按 Enter。
- 工程軌的人不准替規格軌決定需求。發現規格不清楚時，回頭問規格軌，不要自己猜，也不要讓 AI 猜。

**常見失衡**：工程軌太強，規格軌變成旁觀者。看到這種情況，請工程軌暫停打字，改由規格軌口述給 AI。

## 自主期怎麼帶

| 項目 | 做法 |
|---|---|
| 答疑 | 每週一次線上 1 小時，或非同步群組（24 小時內回） |
| 進度追蹤 | 看各組 repo 的 commit 紀錄，不需要學員另外回報 |
| 介入時機 | 某組超過 5 天沒有 commit → 主動私訊 |
| Day 3 前一天 | 收齊各組的「AI 誤解紀錄」，挑出 Day 3 上午要講的例子 |

**最常見的卡關**：第一張票切太大。看到某組 commit 了一大坨程式碼但跑不起來，就請他們把票切薄，重來一次。

---

## 常見的帶課失誤

| 失誤 | 後果 |
|---|---|
| 讓學員原封不動貼提示詞 | 學到打字，學不到判斷。每次都要他們先改成自己的版本 |
| 幫學員定義「做完」 | 學員回公司後，沒有你在旁邊就不知道怎麼驗收 |
| 跳過自主期，4 天連上 | Day 3 變成看示範，學員沒有自己卡住過的經驗可以檢討 |
| 第一天就開放 AI 全自動模式 | 學員不知道 AI 做了什麼，出錯時無從追查 |
| Day 4 只 demo 成功的部分 | 錯過最有價值的內容：失敗的地方與學到的事 |

## 收尾

結訓前請每位學員填寫導入評估表（`3-playbook/`，建置中）。它同時是：

- 學員回公司的健檢工具
- 後續企業包班或顧問諮詢的切入點
