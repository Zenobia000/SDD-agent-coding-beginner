## 每塊在防什麼

**這些不是「範例 code」，是把常見錯誤預先擋掉的成品。**

### `db` — 五個 schema 常見錯誤
```
① 什麼都 nullable    → 只有真的可空的才可空
② 沒有 created_at    → 一定有，且用 UTC
③ 浮點數存錢         → 整數存最小單位（0.1+0.2 != 0.3）
④ 硬刪除            → deleted_at 軟刪除
⑤ 沒有唯一約束       → DB 層 UNIQUE，不靠應用層防
```

### `etl` — Validate 那一段
```
Extract → Transform → Validate ★ → Load
                          │
                    不過就不進 Load
```
**這一行就是「可信管線」和「自動產生髒資料機」的唯一差別。**

四類檢查：筆數變動 / 關鍵欄位非空 / 型別範圍 / 唯一性。
另外處理了**冷啟動**——所有「跟上次比」邏輯的共同盲點。

### `api` — 三件事
```
① 驗證在邊界做一次，未知欄位拒絕（不要靜默忽略）
② 錯誤形狀固定，且絕不吐 stack trace 給使用者
③ 資源存取檢查歸屬 —— 防 IDOR
```
**IDOR 補充**：資源不存在與無權存取**都回 404**。
回 403 等於告訴攻擊者「這個 id 存在」。

### `auth` — 三個攻擊面
```
① 密碼用 scrypt（慢是刻意的），常數時間比對防時序攻擊
② session 一定有過期時間，且能一次踢掉某使用者的全部 session
③ 帳號不存在與密碼錯誤回同一個訊息 —— 防帳號列舉
```

### `frontend` — 六種狀態
```
Loading（延遲 300ms 才顯示，避免閃爍）
Empty  （要給下一步，不只說「沒有資料」）
Error  （圖示 + 文字 + 可點的重試，不只變紅）
Success
Partial（還有更多）
Forbidden
```
**設計稿只畫 Success 那一格。** 其餘五格是你的責任。

## 怎麼裝（正確順序）

```
① /blocks           看你缺什麼
② 跑對應的 skill     定契約（不要直接複製 code）
③ 複製積木          cp -r labs/blocks/<名>/* ./
④ 改成你的          schema、欄位、驗證規則
⑤ /verify + 跑考卷   確認沒退步
```

**第 ② 步不能跳。** 直接複製 code 你只是搬東西，沒有理解契約——
之後改需求就不知道該動哪裡。

## 積木 vs 框架

| | 框架 | 積木 |
|---|---|---|
| 你要學 | 整套規矩 | 一個檔案 |
| 換掉的成本 | 高（重寫） | 低（換那塊） |
| 適合 | 長期大型專案 | 學習與快速驗證 |

**積木的價值在於「可以只拿一塊」。**
你不需要為了存資料學整套 ORM，你需要的是一個能跑的 schema + 一個驗證函式。

## 全端的資料流

```
外部來源 ──etl──> db ──api──> frontend
                    ↑           ↓
                   auth ←──────┘
```

**每個箭頭都是一個契約。契約沒定義清楚的地方，就是之後會壞的地方。**

裝積木前先問：這塊的上游是誰、下游是誰、契約是什麼？
