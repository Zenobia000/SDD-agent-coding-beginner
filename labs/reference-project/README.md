## 結論卡

| | |
|---|---|
| **這是什麼** | 老師完整跑過 S0–S7 的產出物快照 |
| **怎麼用** | 每站結束後，拿你的東西**對照結構**，不是抄內容 |

---

## 為什麼是這個題目

刻意選一個**四拍每一格都填得滿**的題目：

| 格 | 這個題目的答案 |
|---|---|
| 範圍 | 三個固定來源，不做「任意網站」 |
| 評分 | 匯率數字與官方頁面誤差 < 0.01 —— **程式判得出來** |
| 預算 | 一輪 5 次抓取 |

而且它會用到全端的每一塊：
```
三個網站 ──etl──> SQLite ──api──> 網頁 ──> 每日摘要
```

**你的題目不必和它一樣。** 對照的是「欄位的具體程度」，不是內容。

---

## 怎麼對照

### ✅ 該對照的

- **欄位有沒有填滿**（例：現況有沒有三個數字）
- **判準的具體程度**（例：「品質好」vs「誤差 < 0.01」）
- **產出物的結構**（例：考卷有沒有邊界 case 那幾筆）

### ❌ 不要對照的

- 內容本身（你的題目不同）
- 分數高低（老師的基線比你高不代表什麼）
- code 寫法（有很多種對的寫法）

## 給講師

開課前請自己完整跑一遍，並把**你自己的產出**覆蓋到這些 `expected/` 裡。

理由：
- 學員會問「老師你的長什麼樣」，你要拿得出來
- 你會發現哪一站的判準寫得不夠明確
- 實際耗時要回寫進 [`../../curriculum/instructor/timing.md`](../../curriculum/instructor/timing.md)

**用自己的題目做示範**，不要用 rate-digest —— 學員會照抄。
