# /check-sources — 來源健康檢查

> 這是 S5 老師寫的 command 範例。
> **對照重點：frontmatter 格式 + 有「硬規則」段**，不是內容。

## 為什麼寫成 command 而不是別的

| 選項 | 為什麼不是 |
|---|---|
| hook | 這不需要「自動發生」，是我想查的時候才查 |
| skill | 沒有附件、沒有多步驟流程，單檔就夠 |
| subagent | 不會產生大量中間資訊 |
| 直接講 | **我已經講第 4 次了** ← 這就是該包起來的訊號 |

## 步驟

1. 讀 `config/sources.yaml` 取得三個來源的 URL 與 selector

2. 對 `$ARGUMENTS` 指定的來源（留空則三個都查）逐一：
   ```bash
   curl -sS -m 10 -o /tmp/src.html -w '%{http_code}' <URL>
   ```

3. 檢查三件事：
   | 檢查 | 判準 |
   |---|---|
   | 連得上 | HTTP 200 |
   | selector 找得到 | 用 selector 抓，有結果 |
   | 抓到的像數字 | 正規化後能 parse 成 float |

4. 輸出：

```
| 來源 | 連線 | selector | 解析 | 抓到 |
|---|---|---|---|---|
| bank-a | ✅ 200 | ✅ | ✅ | 31.2450 |
| bank-b | ✅ 200 | ❌ 找不到 | — | — |
| bank-c | ❌ timeout | — | — | — |

判定：2 個來源有問題

下一步：<恰好一個動作>
```

## 硬規則

- ❌ **不准自動修 selector** —— 列出問題，讓我決定。selector 改錯會靜默抓到錯的數字
- ❌ **不准超過 10 秒 timeout** —— 這是健康檢查，不是重試
- ❌ **不准寫入資料庫** —— 純唯讀檢查
- ❌ **不准把抓到的完整 HTML 貼出來** —— 只回報結論
- ✅ 三個來源**都要查完**才回報，不要查到第一個壞的就停

## 常見誤判

| 看起來壞了 | 其實 |
|---|---|
| selector 找不到但網頁打得開 | 對方改版了，需要更新 selector |
| 抓到「--」或「暫無報價」 | 非交易時段，不是壞掉 |
| 三個同時 timeout | 通常是你自己的網路，不是對方 |
