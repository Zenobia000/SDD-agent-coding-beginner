# 上半：第 3 站的產出

## 三輪對話跑完後拿到的結構級 prompt

```text
# Role
你是一位擅長「個人財務小工具」的產品設計者兼前端工程師。
你的專長是把一件人人都煩、但沒人願意花二十分鐘處理的小事，
做成一個三分鐘就能用完的工具。

# User Profile
- 25–40 歲上班族，同時訂閱 5–10 個服務
- 其中至少 2 個美金計價、至少 1 個年繳
- 有信用卡但沒有對帳習慣，看帳單只看總額
- 曾經試過用 Excel 管理，填到第 4 筆就放棄
- 技術能力：會用瀏覽器，不會寫程式

# Constraints
1. 所有資料由使用者手動輸入，沒有任何自動匯入管道（銀行 API 拿不到）
2. 絕對不收集信用卡卡號、銀行帳號、任何金融憑證
3. 資料只存在使用者自己的裝置，不上傳
4. 不做帳號系統、不做多裝置同步
5. 不做一般消費記帳，只管「會自動重複扣款」的項目
6. 新增一筆的必填欄位不得超過 3 個 —— 這是產品的生死線
7. 外幣換算使用固定匯率，由使用者自己設定，不抓即時匯率
8. 開發時間：兩個週末

# Output Requirements
- 單頁應用，不換頁
- 主畫面最顯眼的元素是「本月真實總支出」，字級要壓過其他所有東西
- 年繳項目只計入實際扣款月，但要另外顯示平均月成本
- 試用中的項目要計入總額，並以不同顏色區隔
- 提供匯出成 JSON 的功能
- 一筆資料都沒有時，畫面要有引導文字，不能是空白或 0
```

**為什麼這份 prompt 是「規格級」而不是「想法級」**：

| 特徵 | 這份裡的證據 |
|---|---|
| 名詞精確 | 「單頁應用、資料存瀏覽器」，不是「現代化的網頁應用」 |
| 行為可驗證 | 「必填欄位不得超過 3 個」可以數；「介面要好用」不行 |
| 分得開 | Constraints（不能做什麼）與 Output Requirements（要長什麼樣）分開，AI 不會搞混 |

## AI 替我做的假設清單（第三輪的產出）

> **這張表是整門課最值錢的東西。**
> 它把「AI 幫我做決定但我不知道」變成「AI 問我要怎麼決定」。

| # | AI 的假設 | 如果我想法不一樣會怎樣 | 我的裁決 |
|---|---|---|---|
| 1 | 年繳攤平成 12 個月呈現 | 月支出跟真實帳單對不起來 | **改**：顯示在實際扣款月，另給平均月成本 → D1 |
| 2 | 免費試用期算 0 元 | 低估下個月支出，而且無視我最大的痛點 | **改**：算未來月費，用不同顏色標 → D2 |
| 3 | 美金用今天的即時匯率換算 | 每次打開總額都不一樣，沒辦法比較 | **改**：使用者自設固定匯率 → D3 |
| 4 | 「還在用」由使用者手動勾選 | 沒人會去勾，這個功能等於不存在 | **砍掉整個功能** → D4、FR-07 作廢 |
| 5 | 家庭方案記全額 | 高估自己的實際支出 | **接受**（只有一筆，寫在備註）→ D5、開放問題 Q3 |
| 6 | 已取消的訂閱直接刪除 | 看不到自己砍了多少，失去成就感 | **改**：狀態改成 cancelled，保留紀錄 |
| 7 | 金額可以填小數 | 台幣沒有小數，會出現 NT$390.00 這種醜東西 | **接受假設但加限制**：正整數 → NFR-04 |
| 8 | 需要分類與統計圖表 | 5–10 筆資料做分類是過度設計 | **砍掉** → PRD 非範圍 |
| 9 | 要有提醒通知 | 需要瀏覽器授權，會卡住第一次使用 | **延後** → 開放問題 Q2 |
| 10 | 空清單顯示 0 | 第一次打開看到 0 很挫折，不知道下一步做什麼 | **改**：顯示「先填 3 筆看看」 → NFR-04 |

**10 條裡，我改掉或砍掉了 8 條。**

如果我沒跑這一輪，這 8 個決定會由 AI 替我做完，而我要到把東西做出來、用起來覺得不對勁的時候才會發現 —— 那時候資料已經存進去了。

# 下半：第 7 站的 build prompt

> **不要把三份文件整包貼進去。** 平台會被淹沒 —— 它會抓到一堆背景資訊然後在細節上失焦。
> 照下面的順序分四段貼，**每段貼完等它回應再貼下一段**。

## 第 1 段：一次講清楚要做什麼

```text
我要做一個管理「訂閱制服務」的個人小工具。
使用者是同時訂了 5–10 個服務、其中有美金計價也有年繳、
但從來沒有真的算過總共花多少錢的上班族。

核心價值只有一個：讓他在 5 分鐘內看到一個他從沒看過的數字 ——
換算過的真實月支出。

這是一個 POC，只要能跑、能驗證想法，不需要考慮上線、擴充或多人使用。

先不要開始做。請先複述一次你理解的需求，我確認之後再開始。
```

> **「先不要開始做」這句是整段最重要的一句。**
> no-code 平台的預設行為是立刻生一個東西給你看。
> 讓它先複述，你會在三十秒內發現它誤解了什麼 —— 而不是在生完之後。

## 第 2 段：資料先定（最不可逆的部分）

```text
資料模型如下，請完全照這個結構，不要自己增減欄位：

Subscription（一筆訂閱）
- id            唯一編號
- name          服務名稱          例：Netflix
- amount        金額，正整數       例：390
- currency      幣別              TWD 或 USD
- cycle         扣款週期          monthly 或 yearly
- nextChargeAt  下次扣款日        例：2026-09-15
- status        狀態              active / trial / cancelled
- note          備註，自由填寫

Settings（全域，只有一份）
- fxRate        使用者自設的 USD→TWD 匯率，例：31.5

資料存在瀏覽器 localStorage，不上傳任何伺服器，不做登入。
請提供匯出成 JSON 檔的功能。
```

## 第 3 段：功能，一次只給三條

```text
請實作以下功能，每條後面是驗收條件，請確保都滿足：

FR-01 檢視訂閱清單與月支出總額
- Given 已存了至少一筆訂閱
- When 打開頁面
- Then 清單顯示所有訂閱，畫面上方以最大字級顯示本月總支出（台幣），
       且該數字已含年繳攤算與外幣換算

FR-03 新增一筆訂閱
- Given 使用者在清單頁
- When 點「新增」，填入名稱、金額、扣款週期三個欄位並儲存
- Then 該筆立刻出現在清單中，且月支出總額同步更新

FR-05 外幣以自設固定匯率換算
- Given 設定中 USD 匯率為 31.5，且有一筆 USD 20 的月繳訂閱
- When 檢視清單
- Then 該筆在總額中以 NT$630 計入，且清單上同時顯示原幣別金額（USD 20）

做完這三條就停下來，我要先驗收。
```

> **「做完這三條就停下來」**。不加這句，它會順手把你沒要的功能一起做掉，
> 然後你要花更多時間把它們拆出來。

## 第 4 段：非功能需求，最後才給

```text
以下是品質要求：

NFR-02 新增一筆訂閱：不超過 3 個必填欄位、不需要換頁
NFR-03 資料不上傳任何伺服器；關掉分頁再打開，資料仍在
NFR-04 一筆資料都沒有時，顯示「先填 3 筆看看」的引導，
       不是空白畫面、不是 0、不是錯誤訊息；
       金額填負數或文字時顯示「金額請填正整數」，
       停留在表單，已填的其他欄位不消失

請檢查目前的實作是否滿足這三條，不滿足的請修正，
並明確告訴我哪幾條你做不到、為什麼。
```

> **最後一句是關鍵**：主動要 AI 招認它做不到的部分。不問，它不會說。

## 真實的驗收結果

> 這是把上面四段真的跑完之後填的表。**注意它沒有全部打勾。**

| 需求 | 驗收條件（Then） | 實測結果 | 通過？ |
|---|---|---|---|
| FR-01 | 清單 + 最大字級總額，含換算 | 5 筆都在，總額 NT$1,847，字級明顯最大 | 通過 |
| FR-02 | 年繳只計扣款當月 + 顯示平均月成本 | 年繳那筆只出現在 11 月，**但平均月成本沒做** | **未通過** |
| FR-03 | 3 欄位新增，總額同步更新 | 表單有 7 個必填（多了幣別、狀態、日期、備註） | **未通過** |
| FR-05 | USD 20 以自設匯率計入，並顯示原幣別 | 換算對，NT$630；原幣別也有顯示 | 通過 |
| NFR-02 | ≤ 3 個必填欄位、不換頁 | 不換頁 OK，但必填 7 個 | **未通過**（同 FR-03） |
| NFR-03 | 無外部請求；重開資料仍在 | 檢查了瀏覽器網路面板，沒有外部請求；重開資料還在 | 通過 |
| NFR-04 | 空狀態有引導；錯誤輸入不清空表單 | 空狀態有引導；**但填負數會清空整張表單** | **未通過** |

**11 條裡 4 條未通過，而且其中兩條是同一個根因。**

## 用編號改，不要用感覺改

```text
FR-03 與 NFR-02 未通過，是同一個問題。

驗收條件是：新增一筆訂閱，必填欄位不超過 3 個
（名稱、金額、扣款週期）。

目前表單有 7 個必填。請把 currency、status、nextChargeAt、note
改成選填，並給預設值：
- currency 預設 TWD
- status 預設 active
- nextChargeAt 預設空白（之後可補）
- note 預設空白

不要動 FR-01 和 FR-05，那兩條已經驗收通過。
```

對照一下大部分人會怎麼講：**「新增那邊欄位太多了，幫我改一下」**。

差別：

- **引用編號** → AI 知道你在講哪一條，不會順手改壞別的
- **貼上驗收條件** → AI 知道什麼叫「改好了」
- **明確講出改法** → 你已經知道要怎麼改了，不需要讓它再猜一次
- **「不要動已通過的那兩條」** → 這句能省下你一半的來回

## 收尾：第 0 站的問題

> **我要證明什麼**：把訂閱全部列出來、算出真實月支出，就足以讓一個人砍掉至少一個沒在用的訂閱。

**結果**：填完 9 筆，總額 NT$2,180 —— 比我以為的多了大概八百塊。當場砍掉 2 個（一個試用完忘記退的、一個看了半年前最後一次用的）。

**假設成立。** POC 到此為止，可以停了。

真正砍掉的原因不是任何一個功能，是**那個總額數字第一次出現在螢幕上的那一秒**。這件事寫在 PRD §期望成果，但要到真的做出來才知道它是對的。
