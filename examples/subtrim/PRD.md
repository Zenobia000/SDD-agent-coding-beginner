## 1. 問題陳述

每個月被自動扣款的訂閱服務，總額比自己以為的高，而且其中一定有幾個是早就不用了的。

問題不在於「查不到」—— 帳單一直都在。問題在於**查一次的成本太高**：要翻信箱找確認信、要記幣別、要換算年繳，一個人要花二十分鐘，所以沒有人會每個月做。結果是每年只在被某件事觸發時查一次，中間十一個月都在漏錢。

作者上次認真查是去年，一次砍掉三個，月費共 NT$620，其中一筆已經連續付了 8 個月沒用過（NT$1,560）。

---

## 2. 目標使用者

**主要使用者**：25–40 歲上班族，同時訂 5 個以上服務，其中至少 2 個美金計價、至少 1 個年繳。有信用卡但沒在對帳，看帳單只看總額。

**第一版的唯一使用者是作者本人。**

**他現在怎麼解決**：沒有系統性做法。偶爾滑帳單，或刷卡被拒才發現。試過 Excel，填到第四筆就放棄 —— 因為要一筆一筆去信箱翻確認信。

**不是為誰做**：
- 只有 1–2 個訂閱的人（他心算就好，不需要工具）
- 要管公司費用、需要報帳與多人審核的人（那是完全另一個產品）

---

## 3. 使用者主流程

1. 打開，看到空清單與一句「先填 3 筆看看」
2. 點「新增」，填服務名稱、金額、扣款週期，儲存
3. 重複 2，把手上想得到的都填進去
4. 看到畫面上的**真實月支出總額**（年繳已攤算、美金已換台幣）
5. 掃過清單，看到「試用中」的那幾筆被標成不同顏色
6. 決定要砍哪些，去各家官網退訂
7. 回來把砍掉的那幾筆狀態改成「已取消」，看總額下降

**這個流程結束時，使用者得到什麼**：一個他從來沒看過的數字，以及一個他剛剛做出的決定。

## 4. 範圍

### 這版要做

| # | 功能 | 為什麼是這版就要有 |
|---|---|---|
| F1 | 新增／編輯／刪除一筆訂閱 | 沒有它，主流程斷在 step 2 |
| F2 | 顯示真實月支出總額（年繳攤算、外幣換台幣） | **這就是整個產品的價值**。沒有它，這只是一張清單 |
| F3 | 標記試用中的訂閱，視覺上區隔 | 忘記退訂的試用期是作者最大的痛點來源 |

**只有三個。** 想到的其他功能全部在下面。

### 非範圍（明確不做）

| 不做 | 為什麼 |
|---|---|
| 串接銀行／發卡行 API 自動抓帳單 | 個人開發者拿不到，這是硬牆不是選擇 |
| 記錄一般消費（吃飯、購物） | 那是記帳 App。做了就會變成一個爛記帳 App，而不是一個好的訂閱工具 |
| 帳號系統與多裝置同步 | 一個人用不需要。加了它，就得處理密碼、外洩、備份 |
| 自動偵測「有沒有在用」 | 拿不到使用資料。假裝做得到只會給出錯的建議 |
| 匯率即時更新 | 每次打開數字都不一樣，會毀掉「比較」這件事本身。改用使用者自設的固定匯率 |
| 提醒／通知功能 | 需要授權，對 POC 太重。見開放問題 Q2 |
| 分類、標籤、統計圖表 | 5 到 10 筆資料不需要分類。等使用者填到 30 筆再說 |

## 5. 成功指標

| 指標 | 目標值 | 怎麼量 |
|---|---|---|
| 填得完 | 從空白填完所有訂閱 ≤ 5 分鐘 | 作者自己拿手機計時，做完當下量 |
| 單筆速度 | 新增一筆 ≤ 30 秒 | 同上，量第 4 到第 6 筆（前三筆會比較慢） |
| **有用** | 填完後至少砍掉 1 個訂閱 | 作者自己數。**這條是第 0 站的核心假設** |
| 記得回來 | 一個月後主動再打開一次 | 2026-09-15 那週自己確認 |

## 6. 開放問題

| # | 問題 | 什麼情況下我會知道答案 |
|---|---|---|
| Q1 | 「多久沒用」要怎麼讓使用者維護？手動勾選真的有人會做嗎？ | 我自己用滿一個月就知道 —— 如果我自己都沒勾，答案就是不會 |
| Q2 | 提醒要用什麼形式？瀏覽器通知需要授權，可能太重 | 做完第一版、實際錯過一次扣款之後再決定 |
| Q3 | 家庭方案分攤要不要做？記全額會高估自己的支出 | 等我遇到第二個合分的訂閱再說。目前只有一個，先寫在備註欄 |
| Q4 | 使用者自設固定匯率，多久該提醒他更新一次？ | 等匯率真的動超過 5% 而我沒發現的時候 |

## 7. 決策記錄

> 這張表來自第 3 站「AI 替我假設了什麼」的清單。**它是這份 PRD 裡最值錢的一段。**

| # | 決定 | 否決了什麼 | 理由 |
|---|---|---|---|
| D1 | 年繳顯示在**實際扣款的那個月**，另外給一個「平均月成本」 | 年繳一律攤平成 12 個月 | 攤平看起來合理，但會跟真實帳單對不起來。兩個數字都給，各自解決一個問題 |
| D2 | 試用中的訂閱**要算進總額**，用未來月費，並標成不同顏色 | 試用中算 0 元 | 忘記退訂的試用期正是最大痛點來源。算 0 元等於幫使用者無視他最該注意的東西 |
| D3 | 外幣用**使用者自設的固定匯率** | 抓即時匯率 API | 要的是穩定的比較基準，不是精確的財務數字。即時匯率會讓每次打開的總額都不一樣 |
| D4 | **不做**「還在用」的手動勾選 | 讓使用者每月勾一次 | 沒人會去勾。一個沒人維護的欄位，會讓工具給出比沒有還糟的建議。移入 Q1 |
| D5 | 合分的家庭方案**記全額**，差額寫在備註 | 做分攤比例欄位 | 只有一筆這種訂閱。為一筆資料做一個欄位，不划算。移入 Q3 |

**D4 是這份 PRD 最重要的決定** —— 它砍掉的是一個聽起來很棒、實際上會毀掉產品可信度的功能。
