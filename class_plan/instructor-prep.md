# 開課前彩排清單

## 教材與工具
- 兩repo的課程版本一致，`sync-course.py --check`與教材檢查通過。
- 第一天下載Linear固定截圖。太空電梯三影格與動作說明須手動準備；原站有驗證時不臨場等待，改做塔羅或網站臨摹。
- 在授課電腦分別試Claude Code／Codex。帳號能用、skills可讀、MCP真正呼叫、Archify輸出能開；未驗證工具明記。
- Windows、macOS/Linux分別核對Python命令。主線不需LLM API key。

## D1
- 先做唯讀探索、生成、打開網頁。不要從LeaveBot根目錄做自由作品。
- 三題每題8分鐘是製作與操作的預算，不保證第一次成功。保留失敗版本。
- 模型比較固定素材、時間與工具；視覺還原與設計品味分開看。
- 每組只選一題實作，最後產出簡版PRD，至少三條可判斷的條件。

## D2
- 從乾淨main逐張跑A–K。A訪談最多兩輪，將理由／過去日期／重複送出決策寫下。
- 第一次驗一條AC→FR→API→TC，其他由Agent整理、人抽查。
- 骨架僅health；第一個業務紅燈由小組看過。不要把故意失敗的測試當完成狀態。
- 為表單、半天、週末、資料隔離與客戶端狀態寫代表測試，使用暫存SQLite。
- J先分析理由長度200→100，先新增101字失敗測試再改程式；需要修訂既有期待先由人確認。
- K確認實際可啟動、全綠與人工操作，不把Console沒錯當全部驗收。

## Checkpoint
以學生repo的 `course/CHECKPOINTS.md` 與各分支 `course/CHECKPOINT-RECEIPT.md` 為準。開課前確認遠端五分支已發布且來源是同版教材。
保底切換前先保留小組工作、停伺服器、查分支是否存在，再切新rescue分支。只fork main不影響從upstream取得快照。
cp3-tests保留首個預期紅燈；cp4是主線綠燈；cp5含變更與交付範例。這是講師可跑的參考結果，不是每個Agent都能在同時間自行完成的保證。

## 現場取捨
落後15分鐘就協助切保底。工具不通採人工驗收或Mermaid；網路／相依套件卡關先處理環境，不讓Agent猜產品修法。完成主線後才開進階票。
