## 備課時程

### 課前兩週

- [ ] 上課 repo 照 [`leavebot-redesign.md`](./leavebot-redesign.md) 的 P0、P1 改完並合併
- [ ] 在一台乾淨的 Windows 筆電上，照講義 `00-setup.md` 從 fork 做到 `pytest` 全綠，記下每一步實際花的時間
- [ ] 照講義 `03-day2.md` 把 D2 完整彩排一次，邊做邊推 checkpoint 分支（見下方「D2 彩排步驟」）
- [ ] 彩排時遇到的每一個講義錯誤，回頭改講義
- [ ] 跟企業窗口確認：人數、職位分布（決定分組）、公司電腦能不能裝軟體、能不能連 GitHub、npm 與 PyPI

### 課前一週

- [ ] 寄課前通知：講義 `00-setup.md` 的連結、截止日、卡住時寄給誰
- [ ] D1 單元 6 的 Demo 彩排兩次，錄一份完整的螢幕錄影當備案
- [ ] D1 投影片裡所有 `⚠️ 引用前查證` 的地方，查到可靠來源或拿掉
- [ ] 準備五個 cp 分支切換的實測：從每個分支切過去，`pytest` 結果和說明一致
- [ ] 印提示詞卡 A–K（一組一份）、需求簡報卡（`01-brief` 的空白版）、第一步行動卡

### 課前一天

- [ ] 收學員的環境檢核回報；沒完成的人列名單，當天早上 08:30 請他們先到
- [ ] 講師機器：`playground/` 清空、Claude Code 登入、Archify 跑一次 `node .claude/skills/archify/bin/archify.mjs doctor`
- [ ] 確認上課 repo 的 `main` 和每個 cp 分支都是最新的（`.maintain/` 的分支檢查跑過）
- [ ] 手機熱點充電，當網路備案

### 當天早上

- [ ] 08:30 到場，測教室網路：`git clone`、`pip install`、Claude Code 回應時間
- [ ] 白板寫好：checkpoint 切換指令、Wi-Fi、今天的時間表
- [ ] 講師機器開好：終端機字體放大到後排看得清楚、編輯器開檔案樹、瀏覽器分頁準備好
- [ ] 預錄 Demo 影片放在桌面，網路斷了直接播

## D1 單元 6 Demo 腳本

在講師機器的上課 repo 根目錄啟動 Claude Code。所有產出放在 `playground/meeting-room/`，這個資料夾不進版控。
提示詞全文見講義 `appendix/prompt-book.md` 的 D1-1～D1-5。

### 第 23 張｜D1-1 一句話

| 步驟 | 動作 | 預期看到 | 讓學員觀察 |
|---|---|---|---|
| 1 | 貼 D1-1：「幫我做一個會議室預約網頁」，放在 `playground/meeting-room/` | agent 建立 HTML、CSS、JS，可能問你要不要建檔 | 它讀了哪些檔案、建了哪些檔案 |
| 2 | 用瀏覽器打開它產出的 `index.html` | 一個能選日期、時段、會議室的頁面 | 先說好的地方 |
| 3 | 逐一問：會議室幾間？時段單位？資料存哪？要不要填姓名？ | 這些都是它自己決定的 | 填觀察表「我沒說但它決定了的」 |

### 第 24 張｜D1-2 結構化

| 步驟 | 動作 | 預期看到 |
|---|---|---|
| 1 | 挑一份學員在第 19 張改寫的版本；寫得不完整就用講義的 D1-2 | — |
| 2 | 先 `/clear`，貼上，在另一個資料夾 `playground/meeting-room-v2/` 產出 | agent 先列出要改的檔案清單，等你確認（因為 Output Format 這樣要求） |
| 3 | 同意後讓它做完，兩個版本並排開在瀏覽器 | 右邊的會議室、時段、欄位都是指定的 |

D1-2 刻意**不寫**「結束時間不能早於開始時間」和「同一時段不能重複預約」，留給第 27 張。

### 第 25 張｜看工具紀錄

- 往上捲對話，挑一個「讀到錯誤 → 自己修」的片段。沒出錯的話，跑 `git status`（`playground/` 被 ignore，看不到東西，順便講 `.gitignore`），再用 `ls -R playground/meeting-room-v2/` 看它建了哪些檔案。

### 第 26 張｜D1-3 修一個 UI 問題

- 請學員舉手提問題，選一個具體的（按鈕太小、日期格式、送出後沒有提示）。
- 用 D1-3 格式打：「現在 ＜哪裡＞ 是 ＜現況＞，我要的是 ＜期望＞。只改這一處，其他不要動。」
- 改完重新整理瀏覽器。做兩輪。第二輪如果它順手改了別的地方，正好拿來講「只改這一處」為什麼重要。

### 第 27 張｜故意錯誤輸入

依序試，第一個沒漏就試下一個，總有一個會漏：

1. 開始 15:00、結束 14:00
2. 同一間會議室、同一時段，連續預約兩次
3. 預約昨天的日期
4. 會議名稱空白、只填空格
5. 會議名稱填 `<script>alert(1)</script>`

### 萬一 AI 第一次就做得很好

AI 有時候會主動擋下「結束早於開始」。這時候不要硬找錯，換成兩個問題：

- 「它擋了，但這是我要求的嗎？」打開 D1-2 的提示詞，指出沒有任何一句要求它擋。**它這次猜對了，下次可能猜錯，而你不會知道它猜了什麼。**
- 「擋的規則跟我們公司的一樣嗎？」例如它擋了「預約時間不能超過 4 小時」，但這條是它自己發明的。

這樣一來，第 27 張的重點從「AI 會出錯」變成「AI 會替你做決定」，第 28 張的 D1-4 一樣接得上。

### 第 28 張｜D1-4 回顧假設

- 在 v2 的對話裡貼 D1-4，請它列出自作主張的假設。
- 預期 5–10 條。把清單投影出來，全班逐條喊「保留」或「改掉」，講師在對話裡回覆它。

### 第 29 張｜D1-5 PRD 與流程圖

- 先示範一次：D1-5 讓它用 `course/templates/02-prd.md` 寫 `playground/meeting-room-v2/prd.md`，再讓 Archify 畫流程圖。
- 打開流程圖 HTML，對著 PRD 檢查分支。
- Archify 失敗時，當場示範備案：請 Claude Code 在 `prd.md` 裡畫 Mermaid 流程圖，用 VS Code 預覽。

## D2 彩排步驟（同時推 checkpoint 分支）

用一個新的 fork，**完全照講義 `03-day2.md` 做**，不要用講師自己的捷徑。每一步記下實際花的時間。

| 步驟 | 照講義做 | 做完之後 |
|---|---|---|
| 1 | 單元 8：`docs/01-brief.md` | — |
| 2 | 單元 9：卡 A、卡 B，產出 `docs/02-prd.md` | `git switch -c cp1-requirements`，commit，push 到上課 repo |
| 3 | 單元 10：卡 C、D、E，產出 SRS、`diagrams/`、SAD、SDS | 從 cp1 長出 `cp2-design`，commit，push |
| 4 | 單元 11：卡 F、G，產出 `06-test-plan.md`、`issues/`、骨架，只有 health 測試 | 從 cp2 長出 `cp3-tests`，確認 pytest 全綠，push |
| 5 | 單元 12：卡 H，切片全綠 | 從 cp3 長出 `cp4-working-feature`，push |
| 6 | 單元 13：破壞測試（改壞後再修好）、需求變更 | — |
| 7 | 單元 14：卡 K，交付檢查表 | 從 cp4 長出 `cp5-delivered`，push |
| 8 | 進階挑戰 C4、C5：一句話解析、eval、注入測試 | 從 cp5 長出 `advanced-ai-parse`，push |

彩排後：

- 每個分支的 README 頂端加一行：這是哪個時間點的快照、下一步做哪張卡。
- 每一個單元，實際時間超過表定 10 分鐘以上的，回頭砍範圍或改講義，不要指望上課時會比較快。
- 彩排裡 AI 每一次誤解，都是講課時的好例子。記在 `cp5-delivered` 的 `docs/LESSONS.md`。
- `main` 的 `course/` 之後有任何修改，都要一路 merge 到每個 cp 分支。

## 破壞測試腳本（投影片 41）

| 步驟 | 誰 | 動作 |
|---|---|---|
| 1 | 規格軌 | 確認 `.venv/bin/pytest` 全綠 |
| 2 | 規格軌 | 請 AI「告訴我日期順序檢查寫在哪個檔案第幾行，不要改」 |
| 3 | 規格軌 | 自己打開那個檔案，把那一行註解掉，或把 `<` 改成 `<=` |
| 4 | 規格軌 | 跑 `.venv/bin/pytest`，看它變紅。**沒變紅就停下來**：回 `06-test-plan.md` 補一個 TC，這比修好更重要 |
| 5 | 工程軌 | `/clear`，貼卡 I 加上完整的失敗輸出。不說改了哪裡 |
| 6 | 全組 | AI 修完，跑 `git diff backend/tests/`，必須是空的 |
| 7 | 規格軌 | 寫一筆進 `docs/LESSONS.md`：改了什麼、測試怎麼抓到、AI 怎麼修 |

講師示範時用 `<` 改成 `<=`：這樣「開始和結束是同一天」的測試會紅，學員會看到一個意外的測試失敗，比單純刪掉檢查更好講。

## 需求變更腳本（投影片 42）

講師用 PM 的口吻宣布：

> 「人資反映，有員工同一天送了兩張假單。從現在開始：**同一位員工的假單日期不可重疊，待審核的也算。重疊時顯示『這段期間你已經有假單』。**」

預期會冒出來的問題（不要先講，等學員問）：

| 問題 | 給的答案 |
|---|---|
| 同一天的上午和下午算重疊嗎？ | 由各組規格軌決定，寫進 SRS。這就是需求變更的本質 |
| 被駁回的假單算嗎？ | 基本範圍沒有駁回功能，所以目前只有待審核。寫進 SRS 當假設 |
| 錯誤要回什麼 HTTP 狀態碼？ | 由 SDS 決定，409 或 422 都說得通，但要寫下來 |

正確的處理順序：卡 J 出影響清單 → 規格軌核准 → 改 PRD、SRS → 加 TC → 寫測試看紅燈 → 實作 → 跑完整 `pytest`。

## 現場卡關處理

| 狀況 | 第一步 | 超過 5 分鐘還沒解 |
|---|---|---|
| 某台機器 Claude Code 沒回應 | 檢查網路與登入狀態 | 跟組員共用一台，助教繼續修 |
| 整個教室網路慢 | 切手機熱點測試是不是教室的問題 | 講師改播預錄 Demo，學員改做紙上練習（審查 cp 分支的文件） |
| 帳號額度用完 | 確認是個人還是公司方案 | 跟組員共用；講師機器投影帶全班做 |
| `pip install` 卡住 | Ctrl+C，查 Python 版本 | 切 cp 分支也沒用，環境要修；先跟組員共用 |
| Archify 跑不起來 | 確認有 Node 18 以上 | 改走 Mermaid，不要再修 |
| AI 繞圈改不好 | `/clear`，只帶規格和失敗輸出重來 | `/diagnosing-bugs`；再不行切 cp 分支 |
| 一組落後超過 15 分鐘 | 問清楚卡在哪一步 | 切到對應的 cp 分支 |
| 半數以上的組都落後 | 當場砍範圍：40 只要求兩條 TC 綠燈，42 改成講師示範 | 回去調整講義與表定時間 |

## 分組方式

每組 3–4 人，D1 第 30 張當場分組。用學員在 D1 第 03 張寫的便利貼。

| 學員背景 | 軌 | D2 的任務 |
|---|---|---|
| PM、主管、業務 | 📋 規格軌 | 定義問題、確認範圍、審查 AI 產出的需求與驗收結果 |
| SA、SD | 📋 規格軌（設計段可以換到工程軌） | 審查業務流程、需求追溯、API 與資料設計的一致性 |
| 工程師、QA | 🛠️ 工程軌 | 驅動 agent 實作、執行測試、除錯與審查 Git diff |

- 每組至少一位規格軌、一位工程軌。工程師太少時，兩組共用一位會寫程式的人當顧問。
- 全部都是工程師的組：指定一個人輪值規格軌，每個單元換一次。
- 全部都不是工程師的組：講師或助教坐進去當工程軌的副駕，學員負責打指令。

## 成果發表評分

不排名，只給回饋。每組發表後，講師對四項各講一句。

| 項目 | 看什麼 | 好的樣子 |
|---|---|---|
| 成功流程 | 從填表到「我的假單」走得通 | 現場操作，不是截圖 |
| 失敗流程 | 錯誤輸入被擋下，訊息具體 | 訊息和 AC 寫的一字不差 |
| 測試證據 | 說得出一個測試驗的是哪條需求 | 從測試的 `req` 標註找到 SRS 的 FR |
| 一筆誤解 | AI 誤解了哪一句，改了哪份文件 | 改的是規格，不只是程式 |

## 風險與備案

| 風險 | 預防 | 備案 |
|---|---|---|
| 教室網路不穩或擋 GitHub、PyPI | 課前跟 IT 確認；學員課前預熱過 `pip install` | 手機熱點；講師用預錄 Demo；學員審查 cp 分支的文件 |
| 學員帳號額度不足 | 課前通知使用的方案；D2 基本範圍不呼叫模型 API | 組內共用；講師機器帶做 |
| Archify 跑不動 | 課前環境檢核包含 Node 18；課前一天講師跑過 `doctor` | 改用 Mermaid，流程不受影響 |
| 公司電腦不能裝軟體 | 課前請學員先用公司電腦試 | 改帶個人電腦；不行就組內共用 |
| AI 版本更新導致行為改變 | 課前一週彩排一次 | 照預錄 Demo 講；把現場差異當成教材：「這就是為什麼要有規格和測試」 |
| 進度嚴重落後 | 每個檢查點都有 cp 分支 | 見「現場卡關處理」最後一列 |
