# /ops-card — 一頁維運卡

> **核心**：能上線不等於能維運。判準是**「換一個人照著這張卡做，不用回頭問你」**。

## 🚨 自動觸發訊號

### 強訊號
- 「要部署了」「上線」「怎麼回滾」「掛了怎麼辦」「交接給 ___」
- `/sec-scan` 剛通過
- 架構變了（換了 DB、加了背景工作、上了快取）

### 反訊號
- 純本機專案，不會對外提供服務
- 已有維運卡且架構沒變 → 改跑 `/sync-it` 檢查 drift

### 必填七格

````markdown
# 維運卡 — <專案名>

## 1. 這是什麼
<一句話。壞掉的時候誰會有感覺？>

## 2. 長什麼樣
<3–8 個節點的架構圖。超過 8 個就是你該拆服務了>

## 3. 怎麼部署
```bash
<可直接複製執行的指令>
```

## 4. 怎麼確認它活著
| 檢查 | 指令 / 網址 | 正常的樣子 |
|---|---|---|
| 健康檢查 | `curl https://.../healthz` | `200 {"ok":true}` |
| 主流程 | <一個端到端動作> | <預期結果> |

## 5. 壞了先看哪裡（依序）
1. <最常見的成因> → 看 `<哪裡>` → 若是 → 做 `<什麼>`

```

## 7. 什麼情況要找人
| 症狀 | 找誰 | 多急 |
|---|---|---|
````

## 執行步驟

### Step 1：先確認可回滾性（最重要的一步）

逐項問，**不可回滾的操作要當場標紅**：

| 操作 | 可逆嗎 | 若不可逆，怎麼降風險 |
|---|---|---|
| 部署新版程式 | ✅ 通常可以 | 保留前一版 artifact |
| DB migration（加欄位） | ✅ 可以 | — |
| DB migration（刪欄位 / 改型別） | ❌ **不可逆** | 分兩次部署：先停用再刪；先備份 |
| 刪除使用者資料 | ❌ **不可逆** | 軟刪除 + 保留期 |
| 換 API 版本 | ⚠️ 看呼叫端 | 舊版並行一段時間 |

**不可逆的操作一律需要人核准，不進自動流程。**

### Step 2：定義健康檢查

至少兩層，**不能只有 `/healthz` 回 200**：

1. **淺層**：程序活著（`/healthz`）
2. **深層**：主流程真的能跑（打一次真實的端到端動作）

只有淺層檢查的系統，會出現「健康檢查全綠但使用者完全不能用」。

### Step 3：排序失敗模式

**依實際發生過的頻率排，不是依理論可能性。**
第一次寫沒有歷史資料時，用這個預設順序：

```
1. 環境變數 / 設定沒帶到（最常見，且最容易誤診成別的）
2. 依賴的外部服務掛了或改了（API 限流、憑證過期）
3. 資料格式跟預期不一樣（上游改了 schema）
4. 資源不足（記憶體 / 磁碟 / 連線數）
5. 程式本身的 bug（其實最少見）
```

每次真的壞掉後，**回來更新這個順序**——這是維運卡唯一會持續增值的部分。

### Step 4：寫回滾路徑並實際演練一次

```
❌ 「回滾：revert 上一個 commit 然後重新部署」
   —— 沒演練過的回滾等於沒有回滾

✅ 「回滾：
    1. wrangler rollback --message "revert to <deployment-id>"
    2. 確認 curl .../healthz 回 200（約 30 秒）
    上次演練：2026-07-30，耗時 2 分 10 秒
    會失去：這段期間的 KV 寫入（約 N 筆，可從 log 重放）」
```

## 硬規則

- ❌ **不准超過一頁** —— 超過就沒人會在半夜看
- ❌ **不准寫「檢查 log」這種沒有指向的步驟** —— 要寫「看哪個檔案 / 哪個指令 / 找什麼字串」
- ❌ **不准把沒演練過的回滾寫得像已驗證** —— 標「未演練」（`rules/09`）
- ❌ **不准漏掉「不可逆操作」那一格** —— 這是這張卡最重要的資訊
- ✅ 每個指令都要是**可直接複製執行**的，不要 `<your-app>` 這種佔位符

## 部署目標對照（常見選擇）

| 專案型態 | 建議 | 回滾方式 |
|---|---|---|
| 純靜態前端 | Cloudflare Pages / GitHub Pages | 後台一鍵切回上個 deployment |
| 前端 + 輕量 API | Cloudflare Workers / Vercel | `wrangler rollback` |
| 有狀態後端 + DB | Fly.io / Railway | 重新部署上一版 image；**DB 另外處理** |
| 排程工作 / ETL | GitHub Actions cron | 停用 workflow + 重跑上一版 |

換部署目標是 ADR 等級的決策 → 先跑 `/adr`。
