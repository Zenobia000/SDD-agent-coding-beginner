# /blocks — 我現在有哪些積木

> 這是 S6 的入口。**積木不是全部都要裝，是缺哪塊裝哪塊。**

## Step 1：先判斷專案現況

實際去看，不要憑對話記憶：

| 檢查 | 怎麼看 |
|---|---|
| 有 spec 嗎 | `docs/PRD.md` 存在且欄位非空 |
| 有考卷嗎 | `evals/` 目錄存在 |
| 有測試嗎 | `tests/` 存在且跑得起來 |
| 有資料層嗎 | `docs/db-schema.md` 或有 DB 連線設定 |
| 有介面嗎 | 有前端檔案 |
| 有維運卡嗎 | `docs/OPS.md` 存在 |

## Step 2：列積木（依「你現在最需要的」排序）

### 流程積木（skill）

| 積木 | 什麼時候裝 | 核心 |
|---|---|---|
| `/loop` | 要「改到好」而不是「改一次」 | ★ |
| `/decide` | 卡在選型或找不到根因 | ★ |
| `/spec-it` | 還沒有 PRD | ★ |
| `/eval-set` | 講不出「怎麼算做對」 | ★ |
| `/tdd-cycle` | 要開始寫 code | ★ |
| `/verify` | 準備 commit | ★ |
| `/adr` | 有 2 個以上選項在競爭 | |
| `/plan-sprint` | 有 PRD 但不知道先做哪個 | |
| `/sync-it` | 改完 code，文件還沒動 | |
| `/commit-msg` | 要 commit 了 | |
| `/data-pipe` | 要存資料 / 搬資料 | |
| `/ui-spec` | 要做介面 | |
| `/sec-scan` | 準備部署 | |
| `/ops-card` | 準備部署 | |
| `/retro` | 這一輪跑完了 | |
| `/explain-code` | 看不懂 AI 寫了什麼 | |

★ = 核心六塊。其餘依需要啟用。

### 人力積木（subagent）

| 積木 | 什麼時候派 |
|---|---|
| `explorer` | 要在陌生 code 裡定位東西 |
| `test-writer` | 要幫既有 code 補測試 |
| `reviewer` | 重要決策拍板前，需要不同視角 |
| `security-auditor` | 碰到認證 / 金流 / 上傳 / 對外 API |

### 全端積木（可插拔元件）

在課程 repo 的 `labs/blocks/`，每塊都是**可直接複製的最小可用實作**：

| 積木 | 給你什麼 | 對應 skill |
|---|---|---|
| `db` | SQLite schema + migration + 連線封裝 | `/data-pipe` |
| `api` | 一個有驗證、有錯誤處理的 endpoint | `/spec-it` |
| `frontend` | 六種狀態都處理好的資料元件 | `/ui-spec` |
| `etl` | 抽取 → 轉換 → 驗證 → 載入，含冪等 | `/data-pipe` |
| `auth` | 密碼雜湊 + session + 權限檢查 | `/sec-scan` |

## Step 3：給建議（只給一個）

```
你現在有：<列出已具備的>
你現在缺：<最關鍵的那一塊>

建議下一塊：<積木名>
為什麼：<一句話，扣回專案現況>

下一步：<一個動作>
```

## 硬規則

- ❌ **不准建議兩塊以上** —— 一次一塊
- ❌ **不准建議「全部都裝」** —— 積木的價值在於選擇
- ❌ **不准憑對話記憶判斷專案狀態** —— 一定要實際看檔案
- ✅ **已經有的東西要說出來** —— 讓人看到進度，不只看到缺口
