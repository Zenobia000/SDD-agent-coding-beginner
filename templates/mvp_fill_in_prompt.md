# MVP 填空 Prompt 模板（給進度比較慢的學生）

> 用途：直接複製到 **Google AI Studio**，把 `___` 處填上你的內容，按送出即可拿到一份能直接貼進 Antigravity 的 MVP 專案規格與可運行的小型專案（包含前端 + 後端 + README + 環境設定範例）。
> 設計原則：採用 STRIKE 的 **MVP 急救組合 T+K+I**（任務＋驗收＋輸入），三格填好品質就有八成可用。
>
> 不確定填什麼？看每一格底下的「不會填？抄這個」範例直接抄。

---

## 第 0 步：先用一句話寫出你的專案（30 秒）

把下面這句話補完，這就是你今天要做的東西：

> 我要做一個 **___（什麼東西，例如：新聞摘要小網頁）___**，
> 給 **___（誰用，例如：每天早上趕著看新聞的我自己）___** 用，
> 解決 **___（什麼煩惱，例如：每天花 30 分鐘讀新聞還是記不住重點）___** 的問題。

> 不會填？抄這個 👉
> 我要做一個 **「貼新聞內文或網址就出三點摘要」的小網頁**，給 **每天通勤前要快速看新聞的自己** 用，解決 **新聞太多、來不及讀完** 的問題。

你是一位資深的全端工程師兼產品經理，專門幫初學者把模糊的點子做成「結構清楚、能直接擴充」的小型專案。產出要兼顧「初學者讀得懂」與「未來可以加功能」，不要為了極簡而壓成一個檔案。

# 我的需求

【T 任務】
請幫我設計並寫出一個「___（一句話描述你的小工具，例如：貼新聞網址或全文都能出三點摘要的網頁）___」。
最終產出必須包含以下「全部」內容，缺一不可：

1. 一份「給工程師看的 PRD」
   - 功能清單、操作流程、輸入 / 輸出規格、非功能需求

2. 一份「專案資料夾結構說明」（用樹狀圖列出檔案）

3. 一份「完整可直接執行」的多檔案專案 code（每個檔案完整貼出，不要省略）：
   - 前端：`index.html` / `style.css` / `script.js` 三個檔案分開
   - 後端：`server/app.py`（用 Python Flask）或 `server/server.js`（用 Node Express），二選一
     · 後端唯一職責：代收前端請求 → 轉呼叫 Gemini API → 回傳結果（避免 API Key 寫在前端外洩）
   - 環境設定：`.env.example`（列出需要的環境變數，例如 `GEMINI_API_KEY=`）
   - 依賴清單：Python 用 `requirements.txt`、Node 用 `package.json`
   - `README.md`：包含「申請 Key → 安裝 → 啟動 → 怎麼用」四段，每段給可複製的指令

4. 一份「下一步擴充建議」：列 3 個未來可加的功能與大致實作方向（不要動手做，只是告訴我）

【I 輸入】
使用者會在網頁上輸入：___（描述使用者要貼進去 / 點選 / 上傳什麼東西，例如：一段新聞全文文字，或一個新聞網址 URL；後端需自動判斷是 URL 還是純文字，是 URL 就用網路抓網頁 → 抽正文 → 餵給 Gemini）___
範例輸入：
___（貼一個你預期使用者會輸入的真實範例，至少 3-5 行；若支援 URL，附一個範例 URL）___

【K 驗收標準】
必須符合以下條件，否則重做：
- 架構：前後端分離（前端純靜態 + 後端 API），但後端極簡（單檔 < 100 行）
- 介面：簡潔白底、最大寬度 720px、置中、系統字體、繁體中文
- UI 三件套：「輸入區 + 主要按鈕 + 結果顯示區」是核心，可額外加「重置」「複製結果」「載入中提示」
- 技術選擇：
  · 前端：原生 HTML/CSS/JavaScript，不要 React / Vue / 任何前端框架
  · 後端：Flask（Python 3.10+）或 Express（Node 18+），二選一並說明為什麼
  · AI：Google Gemini API（`gemini-2.0-flash`），endpoint = `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent`
  · 網頁抓取（若需求支援 URL 輸入）：
    - Python：`requests` + `beautifulsoup4` 抓 HTML 並抽 `<article>` / `<main>` / 全 `<p>` 純文字
    - Node：`fetch` + `cheerio` 同上
    - 抓失敗（404 / 超時 / 防爬蟲擋）→ 回友善錯誤訊息，不要崩潰
- 安全：API Key **只能放後端**，從 `.env` 讀取（用 python-dotenv 或 dotenv 套件）；前端只呼叫自己的後端 `/api/...`，絕不直接打 Gemini
- URL 抓取的安全：只接 `http://` / `https://` 開頭、限制 timeout（≤ 10 秒）、限制回傳大小（≤ 1 MB）避免被惡意大檔拖垮
- CORS：後端要設好 CORS，前端從本機 file:// 或 http://localhost 都能呼叫
- 錯誤處理：
  · 前端：使用者沒輸入就按按鈕 → 友善提示
  · 後端：API 失敗 → 回 JSON `{ "error": "可讀的中文訊息" }`
  · 前端收到 error → 顯示在結果區（不要當機、不要只 console.log）
- 註解：每個函式上方一行中文註解說明用途
- 期望輸出格式：___（描述你想看到什麼樣的結果，例如：三點條列摘要，每點不超過 40 字）___

## 第 2 步：拿到結果後做這 4 件事

1. **建立專案資料夾** → 依照 AI 給的樹狀圖，照著建立資料夾與檔案，把每個 code block 內容貼進對應檔案
2. **照 README 的 quickstart 跑起來**
   - Python 後端：`pip install -r requirements.txt` → 複製 `.env.example` 為 `.env` → 填 API Key → `python server/app.py`
   - Node 後端：`npm install` → 複製 `.env.example` 為 `.env` → 填 API Key → `node server/server.js`
   - 然後瀏覽器打開 `index.html`（或後端說的網址）
3. **如果有 bug 或不滿意** → 不要自己改 code，回到 AI Studio 直接打：
   ```
   剛剛的專案我跑起來後遇到問題：

   【我做了什麼】
   ___（步驟 1）___ → ___（步驟 2）___ → ___（按了什麼）___

   【預期】___（你以為會發生什麼）___
   【實際】___（真的發生什麼）___
   【錯誤訊息】（瀏覽器 Console 或 terminal 的紅字）
   ```
   ___（貼錯誤訊息）___
   ```

   請告訴我可能原因（A/B/C 選項），我選一個你再動手改，並把要改的「完整檔案」重新給我（不要只給片段 diff）。
   ```
4. **要把專案搬去 Antigravity 繼續做** → 直接複製 AI Studio 給你的 PRD + 資料夾結構貼進 Antigravity，第一句話打：
   ```
   請依照下面這份 PRD 與資料夾結構幫我建立專案，先確認你理解的需求，再列出你打算建立的檔案，等我說 OK 才開始寫 code。
   [貼上 PRD + 資料夾結構]
   ```

## 第 3 步：完全卡關？用「保底題目」直接套

如果你連第 0 步都填不出來，把下面任何一個題目整段貼進第 1 步的模板（已幫你填好），保證能跑出東西：

### 保底題目 A：新聞三點摘要器
- 一句話描述：**貼新聞全文或網址都能**變成三點摘要 + 一句關注角度的網頁
- 使用者輸入：**二選一**——一段新聞全文（純文字，500-2000 字）**或**一個新聞 URL（後端自動抓取 → 抽正文 → 餵給 Gemini）
- 範例輸入：
  - 文字：去 Google 新聞隨便複製一篇貼上
  - 網址：`https://www.cna.com.tw/news/aipl/...` 等任一新聞網址
- 期望輸出格式：三點條列重點（每點 ≤ 40 字）+ 一句「值得關注的角度」
- 技術備註：後端要會「**判斷輸入是 URL 還是純文字**」（regex 看開頭 `http`），URL 就先 fetch + 抽 HTML 正文，失敗給友善錯誤訊息

### 保底題目 B：會議逐字稿轉待辦清單
- 一句話描述：把會議逐字稿變成待辦清單 + 負責人 + 截止日的網頁
- 使用者輸入：會議逐字稿（多人對話，含人名）
- 範例輸入：「Alice：下週前要把報價單寄給客戶。Bob：我負責整理競品分析，週五交。Carol：我跟設計確認 logo 顏色…」
- 期望輸出格式：Markdown 表格，欄位為「待辦事項｜負責人｜截止日」

### 保底題目 C：英文句子翻譯＋文法解釋
- 一句話描述：貼英文句子，輸出中文翻譯 + 文法重點 + 一個替換用法的網頁
- 使用者輸入：一句到一段英文
- 範例輸入：「Despite the heavy rain, the team decided to proceed with the outdoor event.」
- 期望輸出格式：① 中文翻譯 ② 文法結構解析（2-3 點） ③ 同義替換寫法 1 句

## 預期會拿到的專案結構（讓你心裡有底）

AI 跑完後，你應該會看到類似這樣的結構（以 Python 後端為例）：

```
my-project/
├── README.md                # 怎麼跑、怎麼用、怎麼申請 Key
├── .env.example             # 環境變數範本（含 GEMINI_API_KEY=）
├── requirements.txt         # Python 依賴清單
├── index.html               # 前端頁面（純 HTML 結構）
├── style.css                # 前端樣式
├── script.js                # 前端互動邏輯（呼叫後端 /api/...）
└── server/
    └── app.py               # Flask 後端（單檔 < 100 行，代理 Gemini API）
```

或 Node 後端版本：

```
my-project/
├── README.md
├── .env.example
├── package.json
├── index.html
├── style.css
├── script.js
└── server/
    └── server.js            # Express 後端
```

**為什麼這樣分？**
- 前後端拆開 → API Key 不外洩、未來想換 AI 模型只改後端
- 多檔案而非單檔 → Antigravity 接手時更容易擴充（每次只改一個檔）
- 有 README + .env.example → 你寄給朋友他能自己跑起來

## 速查：為什麼這個模板會成功？

| 你做了什麼 | 對應 STRIKE | 為什麼有用 |
|---|---|---|
| 寫一句話描述 | T 任務 | 讓 AI 知道做什麼、產出物是什麼 |
| 給範例輸入 | I 輸入 | 不讓 AI 瞎猜資料長相 |
| 寫驗收條件 | K 驗收 | 把「夠好」量化，避免 AI 過度發揮 |
| （省略 S/R/E） | — | 初學者第一個專案先求能跑，等熟了再補 |

**口訣：T 任務 + K 驗收 + I 輸入 = 八成可用，先求有再求好。**
