# Prompt：修 bug

> 跑起來壞掉、結果不對、按鈕沒反應時用。

---

## 模板（複製這段）

```
程式有問題，請幫我修。

【我做了什麼】
1. ___（你做的第一步，例如：打開 index.html）___
2. ___（第二步，例如：在輸入框貼了一段新聞）___
3. ___（第三步，例如：按了「產生摘要」按鈕）___

【預期看到】
___（你以為會發生什麼，例如：3 秒內出現摘要文字）___

【實際看到】
___（真的發生什麼，例如：按鈕變灰色卡住，沒反應）___

【瀏覽器 Console 紅字】（按 F12 → Console 分頁，把紅字貼這裡）
```
___（貼錯誤訊息，沒有就寫「無」）___
```

【其他線索】
- 我有把 API Key 填好：是 / 否
- 之前能跑、現在不能：是 / 否
- 我剛剛改了 ___：___

請依照 .agents/rules/03-when-stuck.md 的「三個追問」自我檢查後，告訴我可能原因（A/B/C 選項），讓我選擇要先試哪個。

不要直接重寫整個檔案。
```

---

## 為什麼這樣寫

| 這部分 | 為什麼重要 |
|---|---|
| 「我做了什麼」三步驟 | 讓 AI 能「複製」你的操作，找出真正的問題 |
| 「預期 vs 實際」 | 90% 的 bug 解法藏在這個落差裡 |
| Console 紅字 | 程式真正的錯誤訊息，比你描述的更精準 |
| 「給我選項，不要直接重寫」 | 避免 AI 越改越糟、把好的也改壞 |

---

## 自救清單（送出前先檢查）

- [ ] 我有重新整理瀏覽器（Ctrl+R / Cmd+R）
- [ ] 我有把 API Key 換成自己的（不是 `"請貼上你的金鑰"`）
- [ ] 我有把 index.html 存檔（不是還在編輯器裡沒存）
- [ ] 我打開的是最新版本（不是舊的暫存）

四個都打勾還是壞 → 才送 prompt 給 AI。
