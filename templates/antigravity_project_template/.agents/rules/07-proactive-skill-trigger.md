# Rule 07 — Proactive Skill Trigger

> **新手沒有判斷力。所以 AI 要主動偵測情境、主動建議該觸發哪個 skill。**
> 沒有這條 rule，整套 SDD skill 對新手就是裝飾品。

---

## 鐵律

1. **AI 持續監測對話**，比對 8 個 SDD skill 的「🚨 自動觸發訊號」段
2. **偵測到訊號 → 主動建議**，不要等使用者自己想到
3. **不要直接執行** — 永遠先說「要不要跑 /xxx？」等使用者確認
4. **第一次觸發某個 skill 時，附 30 字內白話介紹**：「這個 skill 會幫你 ___」
5. **使用者拒絕 → 不再追問同一個 skill**（除非後續情境再次強烈匹配）
6. **同一回合最多建議 1 個 skill** — 避免轟炸

---

## 偵測時機

每次使用者送訊息時，AI 都要掃過以下三個維度：

| 維度 | 偵測什麼 |
|---|---|
| **語意訊號** | 使用者用詞中是否出現某 skill 的觸發 keyword（見各 SKILL.md 的「🚨 自動觸發訊號」段）|
| **狀態訊號** | 專案當前狀態（例：沒 PRD 就想寫 code、有紅燈卻要 commit、改完 API 沒同步文件）|
| **動作訊號** | AI 自己正準備做的動作（例：準備寫一個技術選擇 → 觸發 `/adr`）|

---

## 觸發優先序（多個 skill 同時匹配時）

從上往下檢查，第一個匹配的就建議：

| 優先級 | Skill | 觸發條件 |
|---|---|---|
| 1 | `/verify` | 即將 commit / push 之前 |
| 2 | `/sync-it` | `/verify` 過了但有檔案改動未同步文件 |
| 3 | `/spec-it` | 沒 PRD / 沒 BDD scenarios 就想寫 code |
| 4 | `/adr` | 對話中出現多個技術選項在比較 |
| 5 | `/plan-sprint` | 有 PRD 但沒 sprint-current.md / 條目都打勾完 |
| 6 | `/tdd-cycle` | 有 spec 但要寫 code 前 |
| 7 | `/commit-msg` | 一切都綠、要 commit 時 |
| 8 | `/retro` | sprint 結束跡象（所有 Now/Next 條目都 done） |

---

## 觸發語氣（這個很重要）

### ❌ 反例 — 強硬命令式

```
你必須跑 /spec-it。
```

```
跑 /adr。
```

```
依規則 04，沒 spec 不能寫 code，請跑 /spec-it。
```

新手看到會反感、想跳過。

### ✅ 正例 — 建議式 + 30 字白話解釋 + 為什麼

```
我注意到你在比較 Gemini 跟 OpenAI — 這算是 ADR 等級的決策（影響整個專案、3 個月後想換很痛）。

要不要跑 /adr？這個 skill 會幫你寫一份 1 頁的決策記錄，未來 AI 看到會自動參考、不會推翻過去選擇。

要 / 不要 / 之後再說？
```

```
你剛說「我想做一個摘要工具」 — 動工前建議先跑 /spec-it。

它會問你 5 個問題後，自動生 PRD + API 規格 + 測試骨架。30 分鐘的事，能省下 3 小時的「再改改」。

要跑嗎？
```

### 語氣三要素

1. **指出我看到什麼**（「我注意到你 ___」）
2. **解釋為什麼這時候要跑**（「___ 等級的決策」「動工前 ___」）
3. **30 字白話 skill 介紹**（不要假設使用者已經懂）

---

## 反訊號（這些情境不要主動觸發）

防止觸發地獄：

- 使用者明確說「不要建議任何 skill」「我自己來」 → 整個 session 安靜
- 使用者剛拒絕某個 skill → 同一個 skill 該 session 不再提
- 純樣式 / 文案 / 註解修改 → 都不需要 skill
- 對話還在「澄清需求」階段 → 不要急著推 skill，先把需求聽清楚
- 使用者正在 debug 跑紅燈 → 不要打斷推 `/verify`，先讓他修完

---

## 新手保護模式（可選，settings.json 設定）

```json
{
  "skillTriggerMode": "proactive-friendly"
}
```

| 模式 | 行為 |
|---|---|
| `proactive-friendly`（預設） | 主動建議 + 30 字解釋 + 等確認 |
| `proactive-strict` | 主動建議 + 引用 rules 條文 |
| `passive` | 只在使用者打 `/xxx` 時觸發，AI 不主動建議 |

進階學員可改 `passive` 自己管控。

---

## 違反這條規則的後果

| 沒主動觸發的後果 | 例子 |
|---|---|
| 新手不知道有 skill | 「我這 sprint 全程沒用 `/spec-it`、最後改了 8 次」 |
| 過了該寫 ADR 的時機 | 3 個月後 AI 把 React 改成 Vue，因為沒 ADR 防 |
| 改了 code 沒同步文件 | drift 累積、文件失去信任、AI 讀錯前提 |
| commit message 變垃圾 | 「fix」「update」「misc」 — 6 個月後 git log 完全沒用 |
| 沒做 retro | 同一個錯誤踩 3 次都沒記取 |

---

## 心法

> **新手需要的不是「更多 skill」，是「會在對的時機提醒他 skill 存在」。**

> **Skill 沒被觸發 = Skill 不存在。**

> **主動提醒 + 解釋為什麼 + 等確認 = 真正可教學的系統。**
